# Quick Task 260423-tk6 — Plan

## Context

Live-testing on RDS22-2 surfaces a lifetime bug: the legacy Spanish app
deletes its own TEMP directory (`C:\TEMP\marc\146\...`) as soon as
`MAPISendMail` returns, expecting a Mail client to have already
"picked up" the files. By the time the Wails app reads the queue JSON
and calls `os.Stat(att.Path)` inside `internal/mapi/gmail.go:144`, the
attachment is gone. Current failure mode: draft creation returns
`attachment not found: …`, which the classifier demotes to the "gmail"
catchall, which logs as `failed: gmail` with no detail.

Marc confirmed: "the app deletes the files when the MAPI call returns
(it expects the mail app to already pick up the files)". Architectural
fix is: the DLL copies attachments into a queue-owned location
*during* `MAPISendMail`, while the caller is still blocked. Also:
"the app should have shown a proper error" — the UI currently shows
only the opaque category. Diagnostic visibility is non-negotiable.

## Design decisions (locked)

1. **On-disk layout.** JSON filename is `msg_<ts>_<sfx>.json`.
   Attachments dir is a *sibling* with the same stem:
   `%LOCALAPPDATA%\go-mapi\queue\msg_<ts>_<sfx>\<original-basename>`.
   This lets the Go side derive the attachments dir trivially from the
   JSON filename.
2. **Copy policy.** The DLL copies each attachment into the stable
   location *before* writing the JSON. If **any** copy fails, nothing
   is written to the queue — instead an `errors\<stem>.error` file is
   created with the reason. Any partially-copied files are removed.
   Rationale: half a message in the queue would produce a silent data
   loss when the user clicks "Create draft" and only some attachments
   make it into Gmail.
3. **Size field.** The DLL populates `attach.size` from the actual
   copied file's bytes (previously hardcoded 0). Small win — makes
   the JSON self-describing and useful to diagnostics scripts.
4. **Cleanup.** The Go side deletes the attachments subdir *whenever*
   it deletes the corresponding JSON (draft success OR explicit
   dismiss). Privacy-first guarantee unchanged: no retention.
5. **Error visibility.** Two layers.
   - **Log line:** log the full Go error alongside the category in
     both `src/app/app.go` CreateDraftForID and `src/app/automode.go`
     draft loop. Diagnostic-only, no behavior change.
   - **UI:** the `auto-draft-result` event payload gains a `reason`
     field (short, user-readable error text). Error toast/queue row
     displays `reason` when present. Tight and surgical — no new
     error categories.
