Create `.github/workflows/version-packages.yml` with this exact content (per CS-06, D-04, D-05):

```yaml
name: Version Packages

on:
  push:
    branches:
      - main

concurrency:
  group: version-packages-${{ github.ref }}
  cancel-in-progress: true

permissions:
  contents: write
  pull-requests: write

jobs:
  version:
    name: Create Version PR
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          # CRITICAL: must use PAT, not GITHUB_TOKEN, so the PR creation
          # triggers CI workflows on the Version Packages PR branch.
          # GITHUB_TOKEN commits cannot trigger downstream CI by GitHub design.
          # See: https://github.com/changesets/action/issues/70
          token: ${{ secrets.CHANGESET_TOKEN }}
          fetch-depth: 0

      - uses: actions/setup-node@v4
        with:
          node-version: 20

      - name: Install dependencies
        run: npm ci

      - name: Create Version PR or tag releases
        uses: changesets/action@v1.7.0
        with:
          # No 'publish' input -- this phase only creates the PR.
          # Publishing workflows are Phase 7 (extension) and Phase 8 (host).
          commit: "chore: version packages"
          title: "Version Packages"
        env:
          GITHUB_TOKEN: ${{ secrets.CHANGESET_TOKEN }}
```

Key design decisions:
- `runs-on: ubuntu-latest` -- the action is shell/git only; no Windows build needed
- `fetch-depth: 0` -- required so changesets can compare full git history
- PAT (`CHANGESET_TOKEN`) passed to BOTH `actions/checkout` (for branch push) AND `env.GITHUB_TOKEN` (for PR creation) -- per CS-05 and verified in changesets/action issue #268
- No `publish` input -- omitting it means the action ONLY creates the Version PR. It does NOT attempt npm publish or create git tags at this point. Tags are created by the action when the Version Packages PR is merged and the action runs again (finding no changesets, it runs the publish step if configured -- this will be added in Phases 7/8)
- No auto-merge -- the PR requires manual merge per D-05, giving a final human gate before publish workflows trigger
- Concurrency group prevents duplicate runs if multiple pushes happen in rapid succession

**Note on CS-04 (per-package git tags):** The tag format `go-mapi-extension@X.Y.Z` and `go-mapi-host@X.Y.Z` is configured via `.changeset/config.json` `privatePackages.tag: true` (done in Plan 01). The actual tag creation happens when the Version Packages PR is merged and the action runs its publish step. In this phase, we configure the infrastructure; Phases 7/8 will add the `publish` input that triggers tag creation.
