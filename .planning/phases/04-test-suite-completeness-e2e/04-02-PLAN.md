<objective>
Deliver CPPTEST-01, CPPTEST-02, and CPPTEST-03: wire doctest into the
interceptor CMake build, write unit tests for the extracted
`message_converter` module, and run them in CI via `ctest` on
`windows-latest`.

Purpose: Prevent regressions in the hand-rolled ANSI/Wide MAPI-to-UTF-8
conversion paths. This code is not exercised by Go or TypeScript tests
and previously had no unit coverage — the Phase 4 audit makes it a
load-bearing gap.
</objective>

Note on requirement wording mismatch: REQUIREMENTS.md mentions function
names `ConvertMessageFromMapi` / `ConvertMessageFromMapiW`, but the actual
exports in `src/interceptor/message_converter.h` are `ConvertAnsiMessage`
and `ConvertWideMessage`. Tests use the real names.

Note on recipient normalization: the C++ `message_converter` does NOT
strip `SMTP:` / `mailto:` prefixes — that's the Go native host's
`normalizeAddress()` responsibility (watcher.go line ~348). The C++ code
passes recipient addresses through verbatim to the JSON file. The CPPTEST-02
recipient test therefore asserts faithful pass-through, not prefix
stripping. The prefix-stripping coverage lives in Go's `TestNormalizeAddress`.
</execution_context>

## Task 2: CPPTEST-02 — message_converter doctest suite

<read_first>
- `src/interceptor/message_converter.h` — full header, function signatures.
- `src/interceptor/message_converter.cpp` — full implementation, branch list.
- `src/interceptor/mapi_types.h` — `MapiMessage`, `MapiMessageW`, `MapiRecipDesc`, `MapiRecipDescW`, `MapiFileDesc`, `MapiFileDescW`, `MAPI_TO` / `MAPI_CC` / `MAPI_BCC` constants.
- `src/interceptor/json_writer.h` — `MailMessage`, `Recipient`, `Attachment` structs.
</read_first>

<action>
Create `src/interceptor/tests/message_converter_tests.cpp`:
  - `#define DOCTEST_CONFIG_IMPLEMENT_WITH_MAIN` + `#include "doctest.h"`.
  - `#include "message_converter.h"`, `mapi_types.h`, `json_writer.h`.
  - `using namespace go_mapi::message_converter;`
  - `TEST_CASE("WideToUtf8 handles nullptr")` — assert empty string.
  - `TEST_CASE("WideToUtf8 converts ASCII")` — assert `L"hello"` → `"hello"`.
  - `TEST_CASE("WideToUtf8 converts non-ASCII UTF-16")` — assert
    `L"résumé"` → `"résumé"` (the UTF-8 bytes `c3 a9 73 75 6d c3 a9`).
  - `TEST_CASE("AnsiToUtf8 handles nullptr")` — assert empty string.
  - `TEST_CASE("AnsiToUtf8 handles ASCII pass-through")` —
    `"hello@example.com"` → `"hello@example.com"`.
  - `TEST_CASE("FilenameFromPath forward slash")` — `"a/b/c.txt"` → `"c.txt"`.
  - `TEST_CASE("FilenameFromPath backslash")` — `"a\\b\\c.txt"` → `"c.txt"`.
  - `TEST_CASE("FilenameFromPath no separator")` — `"file.txt"` → `"file.txt"`.
  - `TEST_CASE("ConvertAnsiMessage null fields")`:
      Build a `MapiMessage` with `lpszSubject = nullptr`, `lpszNoteText = nullptr`,
      `lpRecips = nullptr`, `nRecipCount = 0`, `lpFiles = nullptr`, `nFileCount = 0`.
      Assert: empty subject, empty body, empty recipients, empty attachments,
      `bodyFormat == "plain"`.
  - `TEST_CASE("ConvertAnsiMessage happy path")`:
      Build a `MapiMessage` with ASCII subject `"Test"`, ASCII body `"Body text"`,
      one recipient `{ulRecipClass=MAPI_TO, lpszName="John", lpszAddress="john@example.com"}`,
      and one file `{lpszPathName="C:\\tmp\\file.txt", lpszFileName="file.txt"}`.
      Assert: subject == `"Test"`, body == `"Body text"`, one `toRecipients`
      entry with matching name/address, one attachment.
  - `TEST_CASE("ConvertAnsiMessage recipient class routing")`:
      Three recipients with `MAPI_TO` / `MAPI_CC` / `MAPI_BCC` classes.
      Assert the result buckets them into `toRecipients` / `ccRecipients` / `bccRecipients`.
  - `TEST_CASE("ConvertAnsiMessage preserves SMTP prefix verbatim")`:
      Recipient with `lpszAddress = "SMTP:user@example.com"`. Assert the
      result's address field is exactly `"SMTP:user@example.com"` (pass-through;
      Go native host strips the prefix, not C++).
  - `TEST_CASE("ConvertWideMessage UTF-16 subject")`:
      Wide subject `L"Héllo Wörld"`, wide body `L"UTF-16 body"`. Assert the
      result's subject is the UTF-8 encoding and body matches.
  - `TEST_CASE("ConvertWideMessage filename fallback from path")`:
      File with `lpszFileName = nullptr` but `lpszPathName = L"C:\\tmp\\resume.pdf"`.
      Assert the attachment's `filename` field is `"resume.pdf"`.
  - `TEST_CASE("ConvertWideMessage unknown recipient class routed to TO")`:
      One recipient with `ulRecipClass = 99` — assert it lands in
      `toRecipients` (default branch of the switch).
</action>
