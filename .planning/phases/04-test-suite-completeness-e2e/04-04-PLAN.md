## Task 1: E2E-05 — flakiness spike (research deliverable)

<read_first>
- `tests/e2e/fixtures.ts` and `tests/e2e/extension.spec.ts` — existing
  patterns and known pain points.
- Playwright documentation on `launchPersistentContext` + extensions.
</read_first>

<action>
Write `.planning/phases/04-test-suite-completeness-e2e/04-E2E-SPIKE.md`
covering:
  - **Known failure modes** of `launchPersistentContext` + Chromium
    extensions on Windows CI: service-worker bootstrap races, extension-ID
    timing, HKCU registry write propagation delay, Windows Defender
    scanning the user-data-dir, Chrome "first run" prompts interfering
    with the popup.
  - **Stable wait patterns**:
      - `await extensionContext.waitForEvent('serviceworker', { timeout: 15000 })` instead of polling `.serviceWorkers()`.
      - Explicit `await page.waitForLoadState('networkidle')` after navigating to the popup URL.
      - Poll-with-timeout pattern for waiting on HOST_STATE transitions
        (use `expect.poll`).
      - Retry connectNative on the service-worker side by firing
        `chrome.runtime.sendMessage({action: 'reconnect'})` from the test.
  - **Retry strategy**: Playwright `retries: process.env.CI ? 2 : 0`.
  - **Runner-image workarounds**: `--no-first-run`, `--disable-default-apps`,
    `--disable-extensions-except=<path>`, `--load-extension=<path>`,
    `--no-default-browser-check`. Do NOT disable Defender — flag as a
    "if this is still flaky on CI" follow-up.
  - **Patterns applied to specs**: a short list pointing at the exact
    helper functions in `fixtures-v2.ts` that implement each pattern.
  - A final "unresolved risks" section listing any flakiness sources the
    spike could not eliminate.
</action>

    9. `npx playwright test --config tests/e2e/playwright.config.ts`.
    10. `actions/upload-artifact@v4` for `playwright-report/` on failure.
