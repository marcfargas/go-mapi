## Task 6: TSTEST-05 — service-worker HOST_STATE broadcast tests

<read_first>
- `src/extension/src/background/service-worker.ts` — `transitionHostState`, `connectToNativeHost`, `handleNativeMessage` (READY branch), `broadcastToPopup`.
- `src/extension/src/test/mocks/chrome.ts` — the extended mock (must already include `storage.session` / `alarms` / `notifications` per Task 1).
</read_first>

<action>
Create `src/extension/src/background/__tests__/service-worker.test.ts`.
The test exercises `transitionHostState` indirectly by driving the module
through chrome mock callbacks.

Setup:
  - Before each test, `vi.resetModules()` to re-import the service worker
    fresh so module-level state (`hostState`, `hasShownInstalledToast`)
    starts at the default.
  - Capture the `onDisconnect` / `onMessage` listeners set by the service
    worker on `connectNative()` by letting the mock record them.
  - Use `chromeMock.runtime.sendMessage` as the broadcast observation
    point — assert on its call arguments.

Cases:
  1. **Initial PROBING broadcast** — after import, assert one
     `chrome.runtime.sendMessage` call with `{type: 'HOST_STATE', state: 'PROBING'}`.
  2. **MISSING on disconnect** — fire the `onDisconnect` listener with
     `chrome.runtime.lastError.message = MISSING_HOST_CHROMIUM`; assert a
     `HOST_STATE` broadcast with `state: 'MISSING'` and
     `errorMessage: MISSING_HOST_CHROMIUM`.
  3. **MISSING → READY one-time toast** —
     a. Drive through MISSING (as in case 2).
     b. Re-trigger `connectToNativeHost` via the reconnect alarm
        (fire the `chrome.alarms.onAlarm` listener with `{name: 'reconnect'}`)
        — this should create a new port.
     c. Fire the new port's `onMessage` listener with
        `{type: 'ready', hostVersion: '2.0.0'}`.
     d. Assert a `HOST_STATE` broadcast with `state: 'READY'` AND exactly
        one `HOST_INSTALLED_TOAST` broadcast.
  4. **Repeat MISSING → READY does NOT re-fire toast** —
     a. Continue from case 3's final state.
     b. Drive MISSING again (disconnect + MISSING_HOST_CHROMIUM).
     c. Drive READY again (reconnect + ready message).
     d. Assert exactly ONE total `HOST_INSTALLED_TOAST` broadcast across
        the whole test (the flag is sticky within a session).
  5. **ERROR on unknown disconnect** — fire `onDisconnect` with
     `lastError = UNKNOWN_HOST_ERROR` from the fixture file; assert a
     `HOST_STATE` broadcast with `state: 'ERROR'` and no
     `HOST_INSTALLED_TOAST`.

Notes for implementation:
  - The service worker auto-runs `loadState().then(() => connectToNativeHost())`
    at module import. Await a microtask tick before asserting the initial
    PROBING broadcast.
  - The mock `chrome.runtime.connectNative` returns a fresh port each
    call — track the latest port via a mock factory so tests can drive
    the right listeners.
  - If a test races on module state, skip that specific assertion and
    document it — do NOT add a real `setTimeout` unless unavoidable.

If module-level state proves untestable via side effects alone, document
the limitation in a skipped `test.todo` block WITH a comment explaining
why, rather than modifying production code. A follow-up entry goes in
`04-FINDINGS.md` flagging that `transitionHostState` would benefit from
extraction into a pure helper in a future refactor.
</action>
