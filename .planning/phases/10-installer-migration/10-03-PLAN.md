    ```nsi
    Function AddFirewallRule
      ; D-16: inbound firewall rule for OAuth loopback. Pre-created at install
      ; time so the first sign-in doesn't trigger Windows Firewall's UAC-style
      ; approval dialog (Pitfall 4 — on RDS the dialog appears on the server
      ; console, invisible to the user in the RDP session).
      ;
      ; Using `netsh` over `powershell.exe -Command "New-NetFirewallRule ..."`:
      ;   - single-line ExecWait (no PowerShell quote escaping)
      ;   - works on all Windows 10+ SKUs without the NetSecurity PS module
      ;   - shorter NSIS script
      ;
      ; Rule is scoped to program=$INSTDIR\go-mapi.exe — NOT to a port — so the
      ; firewall only opens inbound on whatever ephemeral loopback port go-mapi
      ; binds for the OAuth loopback server. No broad port exposure.
      ExecWait 'netsh advfirewall firewall add rule name="go-mapi OAuth loopback" dir=in program="$INSTDIR\go-mapi.exe" action=allow profile=any' $0
      DetailPrint "firewall add rule rc=$0"
      ; Do NOT Abort on non-zero rc — an admin may have group policy blocking
      ; this, in which case OAuth on RDS will still hang but on desktop Windows
      ; it works (Windows auto-classifies loopback without the prompt).
    FunctionEnd
    ```

    **Critical rules:**
    - Rule name is the LITERAL string `go-mapi OAuth loopback` (with spaces) — MUST match the uninstall `netsh advfirewall firewall delete rule name="go-mapi OAuth loopback"` in plan 10-04 byte-for-byte. A typo here breaks uninstall.
    - `dir=in` — inbound only (loopback binds accept inbound from 127.0.0.1:0).
    - `program="$INSTDIR\go-mapi.exe"` — NOT `localport=`. Program-scoped rule is narrower (only this specific .exe can receive traffic via this rule) and port-stable (go-mapi's OAuth loopback port is ephemeral).
    - `action=allow` + `profile=any` — applies to all network profiles (Public/Private/Domain) since loopback is always 127.0.0.1.
    - `$0` captures the netsh exit code. Log via `DetailPrint`. Do NOT `Abort` on non-zero.
    - Single quotes around the entire `ExecWait` argument string — NSIS convention when the command line contains double quotes (which `program="$INSTDIR\go-mapi.exe"` does).

    **Do NOT:**

    - Add the delete-on-uninstall counterpart here (plan 10-04's scope)

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Installer (elevated) → `$SMPROGRAMS` (all-users Start Menu) | Admin writes a `.lnk` readable by all users on the machine |
| ApplicationID::Set (via plugin DLL) → Windows Shell IPropertyStore | Plugin DLL loaded from `src/installer/plugins/x86-unicode/` runs inside the installer process |
| Installer → Windows Firewall | netsh writes a machine-wide inbound rule |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-10-03-01 | Elevation of privilege | Firewall rule could expose a broader surface than intended | mitigate | Rule is `program=$INSTDIR\go-mapi.exe` (not `localport=`), so only this specific binary can accept inbound traffic through the rule. The ephemeral OAuth loopback port is not pinned in the rule; go-mapi binds 127.0.0.1:0 and Windows routes matching traffic to that binary. Even if go-mapi is replaced by malware at `$INSTDIR`, it would need admin to write there (UAC-gated). |
| T-10-03-02 | Spoofing | AUMID collision — another app claims `com.marcfargas.gomapi` | accept (low risk) | AUMID is a reverse-domain name owned by marcfargas.com. A malicious app could spoof it, but Windows treats AUMIDs as opaque strings — the real risk is benign collision. No known collision; production AUMID matches Phase 9's runtime AUMID. |
| T-10-03-03 | Tampering | ApplicationID plugin failing silently → Action Center persistence broken (NOTIF-04) | mitigate | `Pop $0` + `StrCmp` check + `DetailPrint` WARNING on non-zero rc. Pester test (plan 10-05 task 5) asserts the stamped AUMID reads back correctly — catches regressions in CI before ship. |
| T-10-03-04 | Denial of service | netsh firewall add fails due to group policy | accept | `DetailPrint` logs rc; installer continues. Documented limitation: on GPO-locked environments, OAuth-via-RDS requires manual firewall rule OR users will see the first-bind dialog on server console (Pitfall 4). This is the same failure mode that existed before the rule; we haven't made it worse. |
| T-10-03-05 | Tampering | AUMID mismatch between installer shortcut and Wails app runtime | mitigate | Both sides use the SAME literal `com.marcfargas.gomapi`: installer hardcodes it in `!define AUMID` (plan 10-01 header); Wails app receives it via ldflags `-X main.aumidOverride=com.marcfargas.gomapi` (plan 10-06). Plan 10-05 Pester verifies both sides match by reading the stamped AUMID from the .lnk and comparing against the expected constant. |
</threat_model>
