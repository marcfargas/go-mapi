<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Installer binary → HKLM registry | NSIS process (elevated) writes machine-wide registry; installer is itself Authenticode-signed in plan 10-06 so the elevation surface is gated on publisher identity |
| Installer binary → `%ProgramData%\go-mapi\uninst\` filesystem | Admin-elevated write of JSON containing a value previously set in HKLM by another installer (Outlook, Thunderbird, etc.) |
| Vendored ApplicationID.dll → NSIS `makensis` build | Plugin DLL is loaded by `makensis` at installer-compile time (CI runner) and bundled into the final signed installer — supply-chain of the plugin matters |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-10-01-01 | Tampering | MAPI handler HKLM registration clobbers existing Mail default | mitigate | `BackupPreviousMailClient` function writes the pre-install value to `%ProgramData%\go-mapi\uninst\previous-mail-client.json` BEFORE `WriteRegStr HKLM "SOFTWARE\Clients\Mail" "" "go-mapi"` — ordering enforced by placing `Call BackupPreviousMailClient` earlier in the Install section than the Default-overwrite line. Upgrade case (current Default already `go-mapi`) explicitly preserves the existing backup rather than overwriting with `"go-mapi"`. |
| T-10-01-02 | Tampering / supply chain | Vendored `ApplicationID.dll` plugin could be swapped for a malicious variant | accept (low risk) | Plugin is downloaded once from the documented sourceforge URL (https://nsis.sourceforge.io/ApplicationID_plug-in) and committed to the repo under `src/installer/plugins/x86-unicode/`. Git history + PR review catch tampering; plan 10-06's SignPath sign of the final `.exe` covers the downstream integrity. Re-vendoring requires explicit user action + PR review. |
