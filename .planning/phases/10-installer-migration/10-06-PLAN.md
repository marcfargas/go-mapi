    name: Installer release

    on:
      push:

    # SIGNPATH_PROJECT_SLUG, SIGNPATH_SIGNING_POLICY_SLUG.
    #
    # OAuth secrets (GOMAPI_OAUTH_CLIENT_ID, GOMAPI_OAUTH_CLIENT_SECRET) come from repo

      actions:  read        # SignPath v2 reads upload-artifact output

    jobs:
      release:
        name: Build + sign + publish installer
        runs-on: windows-latest

        env:
          GOMAPI_OAUTH_CLIENT_ID:     ${{ secrets.GOMAPI_OAUTH_CLIENT_ID }}
          GOMAPI_OAUTH_CLIENT_SECRET: ${{ secrets.GOMAPI_OAUTH_CLIENT_SECRET }}

        steps:
          - name: Checkout
            uses: actions/checkout@v4

          - name: Setup Go 1.25
            uses: actions/setup-go@v5
            with:
              go-version: '1.25'

          - name: Setup Node 20
            uses: actions/setup-node@v4
            with:
              node-version: '20'

          - name: Install Wails CLI
            run: go install github.com/wailsapp/wails/v2/cmd/wails@v2.12.0

          - name: Install MinGW (interceptor build)
            run: |
              choco install mingw --no-progress -y
              echo "C:\ProgramData\chocolatey\lib\mingw\tools\install\mingw64\bin" >> $env:GITHUB_PATH
            shell: pwsh

          - name: Install npm workspaces
            run: npm ci

          # D-26: wails.json info.productVersion is the version authority. Validate it
          # matches the pushed tag (strip leading 'v'). Throws on mismatch.
          - name: Extract + validate version against tag
            id: version
            shell: pwsh
            run: |
              $json = Get-Content src/app/wails.json -Raw | ConvertFrom-Json
              $wailsVer = $json.info.productVersion

                throw "src/app/wails.json is missing info.productVersion — plan 10-06 task 1 did not land."

                Write-Host "workflow_dispatch: skipping tag-vs-wails.json validation (using wails.json=$wailsVer)"
              }
              elseif ($wailsVer -ne $tagVer) {
                throw "Tag $tagVer does not match src/app/wails.json info.productVersion=$wailsVer. Bump wails.json before pushing the tag."
              }
              "version=$wailsVer" | Out-File -FilePath $env:GITHUB_OUTPUT -Encoding ascii -Append
              Write-Host "Release version: $wailsVer"

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Tag push → GitHub Actions | Any maintainer with push access to the repo can trigger a release. Tag protection rules (not configured in this plan) are a separate mitigation concern |
| Workflow → SignPath API | Signing via SignPath Foundation; trust anchored in SignPath's OV certificate + GitHub's actions runtime |
| Workflow secrets → Build environment | SignPath + OAuth secrets injected via `env:` into specific steps; auto-masked in logs by GitHub Actions |
| Signed installer → GitHub Release asset | Authenticode-signed `go-mapi-setup.exe` attached to the release at the stable `latest/download` URL |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-10-06-01 | Tampering | OAuth client_id/secret leaked via workflow logs | mitigate | GitHub Actions auto-masks secret values. ldflags invocation uses `$env:GOMAPI_OAUTH_CLIENT_SECRET` which expands at runtime in the PowerShell step — the literal value never appears in the YAML. No `echo` or `Write-Host` of the secret content. |
| T-10-06-02 | Tampering | Unsigned binary slips into signed release (SignPath skipped due to missing secret + published anyway) | accept (D-24 intentional fallback) | D-24 explicitly permits unsigned publish when SIGNPATH_API_TOKEN is absent. Users get SmartScreen warning on first run; acceptable for an OSS project. Pitfall 10 handling is Phase 11 REL scope. |
| T-10-06-03 | Tampering | Tag-vs-wails.json mismatch → signed release with wrong version number | mitigate | Version validation step throws on mismatch before any SignPath call. Signed artifacts carry the version embedded in the Wails binary (via `-X main.Version`) which matches the git tag by construction. |
| T-10-06-04 | Denial of service | SignPath API outage blocks release | mitigate | D-24 unsigned fallback: if `SIGNPATH_API_TOKEN` is blank, pipeline skips signing. For transient SignPath errors with token present, the action itself retries per SignPath v2 docs. Manual remediation: re-run workflow via `workflow_dispatch` with `dry_run: true` to diagnose. |
| T-10-06-05 | Spoofing | Maintainer account compromise → malicious signed release | accept | Out of scope for this workflow. Mitigated at the GitHub org level (2FA, branch protection, tag protection). SignPath org-level policies can require per-sign approval — outside this plan. |
| T-10-06-06 | Tampering | Wrong SignPath project/policy slug → signing with a cert meant for a different project | mitigate | `SIGNPATH_PROJECT_SLUG` + `SIGNPATH_SIGNING_POLICY_SLUG` are repo secrets pointing at the `go-mapi` SignPath project.
