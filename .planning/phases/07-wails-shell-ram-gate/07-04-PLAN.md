**Author `scripts/measure-ram.ps1`** — PowerShell 5+ compatible (Windows Server 2022 ships PS 5.1 by default). Prefer Pester 5 if already present on the VM; otherwise plain PowerShell. CONTEXT.md §Claude's Discretion permits either.

Script responsibilities:
1. Accept params: `-Session <int>` (session number for output labeling), `-Scenario <cold-start|idle-pre-webview|idle-post-webview>`, `-OutputDir <path>`.
2. Query Private Working Set via performance counter (most accurate for D-01):
   ```powershell
   $counter = Get-Counter -Counter "\Process(go-mapi)\Working Set - Private" -ErrorAction Stop
   $bytes   = $counter.CounterSamples[0].CookedValue
   $mb      = [math]::Round($bytes / 1MB, 2)
   ```
   If multiple `go-mapi*` processes exist (e.g., `msedgewebview2` children), query ONLY the main `go-mapi` process — per D-01, Private Working Set excludes shared WebView2 pages; but msedgewebview2 is a SEPARATE process (not shared pages within go-mapi). Planner decision: measure the `go-mapi` main process only; document that WebView2 child processes are accounted for separately if they appear (note their Private WS too for transparency, but the gate is on the main process per CONTEXT.md §D-01 wording).

   IF CONTEXT.md §D-01 actually means "sum Private WS across go-mapi + its WebView2 children" (ambiguous), add a `-SumWebView2Children` flag and report both values. Include both in VERIFICATION.md and annotate which the gate is applied against.

3. Sample once per invocation; append a CSV row to `$OutputDir/measurements.csv`:
   ```
   timestamp,session,scenario,iteration,process_name,private_ws_mb
   2026-04-13T12:34:56Z,1,idle-post-webview,1,go-mapi,63.42
   ```

4. Log to console with human-readable summary.

**Run the D-03 protocol.** Inside N RDP sessions concurrently:
- **Scenario A — cold start**: launch `go-mapi.exe`, wait 5 seconds (tray icon stable), run `measure-ram.ps1 -Scenario cold-start -Iteration 1`.
- **Scenario B — 5-min idle (pre-WebView2-init)**: DO NOT open the main window. Wait 5 minutes from launch. Run script with `-Scenario idle-pre-webview`. The WebView2 process should NOT have spawned yet (StartHidden: true).
- **Scenario C — 5-min idle (post-WebView2-init)**: open the main window via tray (this triggers WebView2 init). Close it back to tray. Wait 5 minutes. Run script with `-Scenario idle-post-webview`.
- Repeat all three scenarios 3 times per session (3 iterations × 3 scenarios × N sessions = 9N samples).

Automate where possible:
- A wrapper `scripts/measure-ram-runbook.ps1` (optional) loops the three scenarios for one session with timed sleeps.
- Running across N sessions concurrently is manual (one RDP per session) — document in `scripts/provision-hetzner-vm.md` that each session operator runs the runbook.

**Compute statistics.** After all CSV rows collected, a small aggregation block in `measure-ram.ps1 -Aggregate <csv-path>` produces:
- Mean Private WS per scenario (across all N sessions × 3 iterations)
- Max Private WS per scenario
- Per-session variance (stddev across 3 iterations) — if stddev > 20% of mean, flag a warning per PITFALLS §1

|----------|-------------|

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-40 | Spoofing | RDP brute-force on Hetzner VM public IP | mitigate | User sets a strong admin password (documented in provision-hetzner-vm.md); Hetzner firewall restricts port 3389 to user's source IP; VM is short-lived (destroy after measurement). |
| T-07-41 | Tampering | Binary altered during transfer to VM | accept | Measurement is internal; binary is not a release artifact. SHA256 of `src/app/build/bin/go-mapi.exe` noted in VERIFICATION.md for traceability. Release-artifact signing is Phase 10 (SignPath) concern. |

| T-07-43 | Repudiation | Measurement methodology disputed later | mitigate | Protocol + raw CSV committed to repo; reproducible via `scripts/measure-ram.ps1` + `scripts/provision-hetzner-vm.md`. |
| T-07-44 | Denial of Service | Hetzner VM quota / billing overrun | accept | User's cost decision; short-lived VM hourly billing. Documented in provision doc as "destroy after measurement". |
</threat_model>
