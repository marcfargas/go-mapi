### 1. `scripts/azure-ram-gate.ps1` — Azure orchestration (runs on local dev machine)

Orchestration steps (each wrapped with `Write-Host` progress markers and `try/finally` around the teardown):

1. **Preflight:** verify `az --version` ≥ 2.50; verify `az account show` returns a logged-in principal; set subscription if `-SubscriptionId` passed; refuse to proceed without `-Confirm` (print cost estimate `~$0.41 for 1-hour N=$N run` and exit 2).
2. **Resource group:** `az group create --name $RgName --location $Location`.
3. **VM create:**
   ```
   az vm create `
     --resource-group $RgName `
     --name gomapi-ramgate-vm `
     --image MicrosoftWindowsServer:WindowsServer:2022-datacenter:latest `
     --size $VmSize `
     --admin-username gomapiadmin `
     --admin-password <generated strong password — use [System.Web.Security.Membership]::GeneratePassword or equivalent> `
     --nsg-rule NONE `
     --public-ip-sku Standard `
     --output json
   ```
   Store the generated admin password in memory only (never write to disk or CSV).
4. **Bootstrap via `az vm run-command invoke`:** execute a PowerShell bootstrap block on the VM that:
   - Creates N test users `ramtest1..ramtestN` with generated passwords.
   - **Adds each user to the local `Performance Log Users` group** (REVIEWS HIGH / measurement gotcha — without this, `Win32_PerfRawData_PerfProc_Process` returns empty). Use `Add-LocalGroupMember -Group 'Performance Log Users' -Member $user`.
   - Downloads the Evergreen WebView2 bootstrapper (`https://go.microsoft.com/fwlink/p/?LinkId=2124703`) and runs `/silent /install`. Confirm via `HKLM:\SOFTWARE\WOW6432Node\Microsoft\EdgeUpdate\Clients\{F3017226-FE2A-4295-8BDF-00C3A9A7E4C5}\pv`.
   - Creates `C:\gomapi\` and waits for binary upload (step 5).
5. **Upload the Plan 03 binary:** use `az vm run-command invoke --command-id RunPowerShellScript` to transfer `go-mapi.exe`. Preferred shape: base64-encode the local binary and inline it in a `[System.IO.File]::WriteAllBytes()` call; if the binary exceeds the `run-command` payload cap (~32 KB script), fall back to staging via a transient Storage Account + SAS URL + `Invoke-WebRequest` inside the VM (document which path was taken in the SUMMARY). Record SHA256 of the uploaded binary into `07-VERIFICATION.md` for traceability.
6. **Upload `scripts/measure-ram.ps1` to the VM** via the same mechanism (it's small, inline is fine).
7. **Kick off the measurement:** invoke `measure-ram.ps1` on the VM in `-Orchestrate` mode with `-N $N` — this triggers the in-VM per-user scheduled tasks (see measure-ram.ps1 spec below). 8. **Pull the CSV back:** use `az vm run-command invoke` to base64-encode `C:\gomapi\phase-07-ram-gate.csv` and write the contents to `$CsvOut` on the dev machine.
9. **Teardown (always runs in `finally` block, unless `-KeepResourceGroup`):** `az group delete --name $RgName --yes --no-wait`. Print the actual run cost (from `az consumption usage list`) if available, else estimate from runtime.

### 2. `scripts/measure-ram.ps1` — On-VM benchmark orchestrator + per-session sampler

PowerShell 5+ compatible. Two modes:

**`-Orchestrate -N <int>` mode** (invoked once, from VM admin user via azure-ram-gate.ps1):
- For each user `ramtest1..ramtestN`, `Register-ScheduledTask -Principal $user -LogonType Password -Action "powershell -File C:\gomapi\measure-ram.ps1 -Worker -User $user"`. Start all tasks near-simultaneously (`Start-ScheduledTask`) to approximate RDS concurrency.
- Watch for all N per-user flag files `C:\gomapi\done-ramtest<i>.flag`. Once all present (or 20-min timeout per user), collate per-user CSV fragments into `C:\gomapi\phase-07-ram-gate.csv` and drop the final `C:\gomapi\measurement-complete.flag`.

**`-Worker -User <name>` mode** (invoked inside each scheduled task, running as that user):
- Launch `C:\gomapi\go-mapi.exe` under the current user.
- Wait 5 seconds → sample `cold-start` (iteration 1).
- Wait until 5 min elapsed from launch → sample `idle-pre-webview` (iteration 1). Ensure main window was NEVER toggled (pre-WebView2-init).
- Trigger the main-window toggle (simulate tray click — may require a small helper; if non-trivial, accept opening the window programmatically via Wails runtime IPC or direct command-line `--show-window` if Plan 03 exposed one; otherwise document that this sample required user-facing simulation and capture `idle-post-webview` with whatever path works). Close it back to tray. Wait 5 min → sample `idle-post-webview` (iteration 1).
- Repeat all three scenarios for iterations 2 and 3.
- Close `go-mapi.exe`; write `C:\gomapi\done-ramtest<i>.flag`.

**Sampling logic (shared by both modes, REVIEWS HIGH multi-process correlation):**
```powershell
$sessionUser = $env:USERNAME
$goMapiProcs = Get-CimInstance Win32_Process -Filter "Name='go-mapi.exe'" |
    Where-Object { (Invoke-CimMethod -InputObject $_ -MethodName GetOwner).User -eq $sessionUser }
foreach ($gm in $goMapiProcs) {
    $gmPid = $gm.ProcessId
    $wvChildren = Get-CimInstance Win32_Process -Filter "Name='msedgewebview2.exe' AND ParentProcessId=$gmPid"

    # Private Working Set via perf counter (D-01 — excludes shared pages).
    # Note: Get-Counter instance name disambiguation across multiple go-mapi processes
    # uses the PID suffix (Windows appends "_<pid>" to duplicate instances when
    # "Show processes in Performance Monitor with their process identifier" is set;
    # otherwise fall back to Win32_PerfRawData_PerfProc_Process keyed by IDProcess).
    $gmWsBytes = (Get-CimInstance Win32_PerfRawData_PerfProc_Process `
        -Filter "IDProcess=$gmPid").WorkingSetPrivate
    $gmWsMb = [math]::Round($gmWsBytes / 1MB, 2)

    $wvWsMb = 0
    foreach ($wv in $wvChildren) {
        $b = (Get-CimInstance Win32_PerfRawData_PerfProc_Process `
            -Filter "IDProcess=$($wv.ProcessId)").WorkingSetPrivate
        $wvWsMb += [math]::Round($b / 1MB, 2)
    }
    $totalWsMb = [math]::Round($gmWsMb + $wvWsMb, 2)

    [PSCustomObject]@{
        iteration      = $Iteration
        session_user   = $sessionUser
        scenario       = $Scenario
        go_mapi_pid    = $gmPid
        go_mapi_ws_mb  = $gmWsMb
        webview2_ws_mb = [math]::Round($wvWsMb, 2)
        total_ws_mb    = $totalWsMb
        timestamp      = (Get-Date).ToString('o')
    } | Export-Csv -Path $OutputCsv -Append -NoTypeInformation
}
```

CSV path on VM: `C:\gomapi\phase-07-ram-gate-<user>.csv` per worker; Orchestrate mode concatenates into the final canonical CSV.

**`-Aggregate <csv-path>` mode** (optional, for post-pull analysis on dev machine): reads the CSV and prints mean `total_ws_mb` per scenario (across all N sessions × 3 iterations), max `total_ws_mb`, per-session stddev across 3 iterations — if stddev > 20% of mean, flag warning per PITFALLS §1. Prints mean `go_mapi_ws_mb`-only as secondary diagnostic.
