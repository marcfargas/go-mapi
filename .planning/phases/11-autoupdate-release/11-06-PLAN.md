<objective>
Add an end-to-end Playwright harness driving the real Wails app through WebView2's
CDP endpoint, with a thin `//go:build e2e` shim that swaps the keyring and Gmail/OAuth
endpoints for fakes the harness controls.

Purpose: the Phase 11 manual smoke surfaced four regressions (queue-row not removed
after Create-draft, Dismiss had no visible effect, multi-arrival appeared as
"overwrite", watcher dispatch race) that Vitest with mocked bindings could not catch.
The roundtrip Go-side mutation → Wails event → Svelte re-render → user action → back
binding is exactly where the regression class lives. This plan establishes the
foundation so any future regression of that class is caught by `npm run e2e` before
ship.

Output: `tests/e2e/` workspace with Playwright + harness + 5 baseline tests, an
e2e-tagged auth/endpoints shim, an npm script + PowerShell launcher, and
`.gitignore` updates. CI integration is OUT OF SCOPE for this plan — local runs are
the GA gate; a follow-up phase wires this into a Windows-runner workflow.
</objective>

Existing seams this plan reuses:

- `KeyringStore` interface in `src/app/auth.go` — `realKeyringStore` wraps
  `zalando/go-keyring`; an in-memory fake exists for tests. The e2e shim will
  install the fake at `NewApp` construction time when the `e2e` build tag is set.
- `gmailBaseURLOverride` package var in `internal/mapi/gmail.go` — endpoint base
  for `httptest`-style overrides. The shim also writes this from env at startup.
- `tokenEndpointOverride`, `revokeEndpointOverride` package vars in
  `src/app/auth.go` — same pattern for OAuth endpoints.
- `EmailWatcher` writes JSON files to `watchDir` under `%TEMP%\go-mapi\` by
  default; the harness boots the app with `GOMAPI_E2E_WATCH_DIR=<tempdir>` so
  each test gets an isolated dir.

Locked decisions:
- D-E2E-01: WebView2 CDP via `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS=--remote-debugging-port=$PORT`.
- D-E2E-02: Build-tag isolation — e2e fakes only compile under `-tags e2e`.
- D-E2E-03: One Playwright worker (single WebView2 instance, port reuse).
- D-E2E-04: Local-only for this plan — CI integration is a follow-up.

    Add `src/app/auth_e2e.go` under `//go:build e2e`. The init function:

    1. Reads `GOMAPI_E2E_FAKE_TOKEN_JSON` from env. If non-empty, parses it as the
       OAuth token JSON and stuffs it into a process-wide fake keyring store that
       `AuthManager` uses instead of `realKeyringStore`.
    2. Reads `GOMAPI_E2E_GMAIL_BASE_URL` and writes it to `mapi.GmailBaseURLOverride`
       (export the existing var if needed).
    3. Reads `GOMAPI_E2E_TOKEN_ENDPOINT` and `GOMAPI_E2E_REVOKE_ENDPOINT` and writes
       them to the existing endpoint override vars in `auth.go`.
    4. Reads `GOMAPI_E2E_WATCH_DIR` — when set, paths.go's `WatchDir()` returns this
       absolute path instead of `%TEMP%\go-mapi\`.

    Add a non-`e2e`-tagged stub (`auth_e2e_stub.go` with `//go:build !e2e`) so
    production builds get the no-op alternatives. `auth.go` exposes a
    `keyringStoreFactory func() KeyringStore` package var defaulting to
    `newRealKeyringStore`; the e2e shim swaps it before `NewApp` constructs the
    AuthManager.

    `main.go`: no behavioural change in production; under `-tags e2e` the init
    in `auth_e2e.go` runs first and the overrides are applied. Gate startup
    OAuth-credentials check on `keyringStoreFactory` not being the test factory
    (so e2e builds don't trip `checkOAuthCredentials`).
  </action>
  <verify>
