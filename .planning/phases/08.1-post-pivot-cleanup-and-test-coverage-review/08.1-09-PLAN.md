    **§Architecture block:**

    Pattern Overview:
    - Two components linked by filesystem IPC: C++ MAPI DLL (writes JSON) + Go/Svelte Wails app (watches + processes).
    - Privacy-first: no retention — emails are deleted from `%TEMP%\go-mapi\` after draft creation or dismissal.
    - Single Wails process owns: tray, main window, watcher goroutine, auth manager, Gmail client.
    - Minimal dependencies; stdlib preferred; no chrome APIs anywhere.

    Layers:
    - **MAPI Interceptor (C++ DLL, `src/interceptor/`)** — Intercepts `MAPISendMail`/`MAPISendMailW`; writes email JSON to `%TEMP%\go-mapi\`. Unchanged from v1.
    - **Shared core (`internal/mapi/`)** — Email parsing, validation, normalization (protocol.go), file watcher (watcher.go), Gmail HTTP client (gmail.go). Imported by the Wails app.
    - **Wails App (`src/app/`)** — Main process: Wails OnStartup/OnShutdown, tray integration, single-instance mutex, session-end handler, watcher bridge, AuthManager (OAuth + keyring), App-struct bindings exposed to frontend.
    - **Frontend (`src/app/frontend/`)** — Svelte 5 UI: welcome / sign-in screen, pre-auth explainer modal, re-auth banner, signed-in header, queue view (queue view lands in Phase 9).
    - Build-tag split: fatal startup guards (e.g., `checkOAuthCredentials`) extracted to non-`bindings`-tagged files so `wailsbindings.exe` can introspect types without `os.Exit`-ing.

    Data Flow:
    - DLL → `%TEMP%\go-mapi\*.json` → fsnotify → watcher goroutine → WatcherBridge → Wails `EventsEmit("queue-changed", ...)` → Svelte `EventsOn("queue-changed")` → UI refresh (`GetQueue` binding → Go returns queue snapshot → frontend renders).
    - User action (e.g., Create draft) → Svelte `SignIn()`/`CreateDraft()` binding call → Go App struct → AuthManager (refresh-if-near-expiry) → GmailClient (stateless) → Gmail API → delete JSON on success.

    Key Abstractions: `MailMessage`, `WatcherBridge`, `AuthManager` (with `KeyringStore` interface seam — real implementation wraps zalando/go-keyring; in-memory fake for tests), `GmailClient` (stateless; receives token per call).

    Entry Points:
    - `src/interceptor/main.cpp` — DLL entry.
    - `src/app/main.go` — Wails app entry; calls `NewApp()`, `wails.Run(...)`.
    - `src/app/frontend/src/main.ts` — Svelte app entry.

    Error Handling: Errors wrap with `%w`; returned from deep functions; top-level handlers log via `%APPDATA%\go-mapi\app.log` + surface to UI via AuthManager events (e.g. `auth-changed {authenticated:false, error: "..."}`).

    Cross-Cutting: Logging = timestamped RFC3339 + `[INFO]`/`[ERROR]` prefix. Input validation at boundary layers (validator on JSON parse; typescript strict mode at frontend). Auth = PKCE loopback with keyring. Privacy = delete-on-process, session-only UI state, no telemetry.

    - Go as the primary language — the v2.x Go native host + RFC 2822 MIME builder + Gmail client code survives the pivot and lives in `internal/mapi/`.
