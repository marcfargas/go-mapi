## Warnings

### WR-01: `TestAuthCodeURLHasPKCE` is `t.Parallel()` while mutating package-level `oauthClientID` / `oauthClientSecret`

**File:** `src/app/auth_test.go:180-186`
**Issue:** `TestAuthCodeURLHasPKCE` calls `t.Parallel()` (line 181) and immediately writes package-level vars `oauthClientID` / `oauthClientSecret` (lines 183-184). Today no other parallel test in the package reads or writes those vars, so there is no live data race. However the combination is fragile:
- Any future parallel test added to `auth_test.go` that calls `newOAuthConfig()` (which reads `oauthClientID`/`Secret` via closure in `auth.go:232-245`) will race.
- The pattern contradicts the explicit non-parallel convention used by every other test that mutates these vars (`TestCheckOAuthCredentials_*` in `credentials_check_test.go` correctly omits `t.Parallel()`).
- Under `-race`, the race detector will fire the day somebody adds a sibling parallel test.

The `TestCheckOAuthCredentials_*` tests don't actually race against this at runtime because Go runs sequential tests first, then parallel ones. But the guard is one careless PR away from breaking.
**Fix:** Drop `t.Parallel()` on line 181. The test takes microseconds; parallelism is not meaningful here and the invariant "tests that write package-level vars run sequentially" is worth protecting.
```go
func TestAuthCodeURLHasPKCE(t *testing.T) {
    // NOTE: not t.Parallel — mutates oauthClientID / oauthClientSecret.
    oldID, oldSecret := oauthClientID, oauthClientSecret
    t.Cleanup(func() { oauthClientID = oldID; oauthClientSecret = oldSecret })
    oauthClientID = "test-client.apps.googleusercontent.com"
    oauthClientSecret = "test-secret"
    // ...
}
```
Also consider restoring the previous values rather than zeroing (line 185 today) — `oauthClientID = ""` is a destructive cleanup if a `-ldflags` value was injected at build time.

### WR-02: Bootstrap tests leak an async goroutine that calls the real Google userinfo endpoint

**File:** `src/app/auth_test.go:607-627, 810-842`
**Issue:** `TestBootstrapAuthSignedInPath` and `TestBootstrapAuth_TransientErrorKeepsTokens` call `app.bootstrapAuth()` which (per `auth.go:780-785`) spawns a goroutine that calls `am.fetchUserInfoLocked(a.ctx)`. Neither test sets `userinfoEndpointOverride`, so `userinfoEndpoint()` returns `https://www.googleapis.com/oauth2/v3/userinfo`. Consequences:
1. **Real outbound network egress from unit tests.** Violates hermeticity. CI sandboxes that block egress (or flaky DNS) will produce logged errors. On `windows-latest` with open egress, the test makes a live request with a bogus bearer token ("about-to-expire" / "a") — Google returns 401 and the goroutine logs + returns.
2. **Leaked goroutine at test exit.** The goroutine can outlive the test (default 10s HTTP timeout on `fetchUserInfoLocked`'s client — `auth.go:368`). If `go test` exits while it's still in-flight, the socket is torn down; fine, but under `-race` any field access ordering that happens after the test's cleanup could show up as a spurious race. Today the goroutine only touches `am.*` under `am.refresh.Lock()`, so it is actually race-safe — but fragile to future refactors.
3. **Slow when egress is blocked.** 10s timeout per test multiplies quickly if tests are retried.

`fetchUserInfoLocked` does NOT panic on `nil ctx` because `http.NewRequestWithContext` returns an error for nil, not a panic (`auth.go:362-365`), so the goroutine logs `oauth userinfo: build request: nil Context` and exits. No test assertion depends on this.
**Fix:** Set `userinfoEndpointOverride` in both tests to a short-lived `httptest.Server` that 401s (matching real behaviour for an invalid token), and synchronously wait for the bootstrap goroutine to complete before asserting. Example:
```go
userinfoSrv := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
    w.WriteHeader(401)
}))
defer userinfoSrv.Close()
userinfoEndpointOverride = userinfoSrv.URL
t.Cleanup(func() { userinfoEndpointOverride = "" })
// ... run bootstrapAuth ...
// Wait for the async userinfo goroutine by briefly acquiring the same lock.
app.auth.refresh.Lock()
app.auth.refresh.Unlock()
```
Even simpler: refactor `bootstrapAuth` to return a `*sync.WaitGroup` or a done channel for the async userinfo fetch, so tests can `.Wait()` explicitly. Lowest-cost fix: just add the stub server.

## Info

### IN-01: `wails CLI` pinned to `@latest` is a supply-chain risk (CI-only, documented)

**File:** `.github/workflows/build.yml:112-113`
**Issue:** `go install github.com/wailsapp/wails/v2/cmd/wails@latest` re-resolves to whatever the Wails org publishes each CI run. If an upstream compromise ships a malicious Wails CLI, every PR build re-pulls it. Plan 07 SUMMARY §key-decisions explicitly accepts this ("can pin later if upstream breaks Go 1.25 build"). Acceptable for v0.x iteration, but worth re-visiting before v3.0 ships.
**Fix:** Pin to the current tag when Phase 11 approaches. Example:
```yaml
- name: Install Wails CLI
  run: go install github.com/wailsapp/wails/v2/cmd/wails@v2.12.0
```
Add a renovate/dependabot lane for the pin.

### IN-02: `TestAuthCodeURLHasPKCE` cleanup zeroes vars rather than restoring prior values

**File:** `src/app/auth_test.go:185`
**Issue:** `t.Cleanup(func() { oauthClientID = ""; oauthClientSecret = "" })` — if a future test or a dev-build injects real values via `-ldflags`, this test permanently wipes them for subsequent tests in the same binary run. The `credentials_check_test.go` tests correctly save/restore:
```go
oldID, oldSecret := oauthClientID, oauthClientSecret
t.Cleanup(func() { oauthClientID = oldID; oauthClientSecret = oldSecret })
```
Today it happens to work because no tests in the binary run with pre-populated values. Future proofing.
**Fix:** Match the save/restore pattern from `credentials_check_test.go:20-24`. Trivial 3-line change.

### IN-03: `svelte-check` pre-existing a11y warning in `App.svelte:129` carried forward

### IN-04: CI workflow does not constrain `wails build` output path / artifact pollution

**File:** `.github/workflows/build.yml:117-124`
**Issue:** `wails build -platform windows/amd64` produces `src/app/build/bin/` which is uploaded wholesale (`path: src/app/build/bin/`). The artifact includes the final unsigned `go-mapi.exe`, which is fine for review/debug but is publicly downloadable from any PR's workflow run. Not a secret leak (binary compiled with empty ldflags, so OAuth creds aren't embedded), but a third party could download and trivially repackage the go-mapi app. Release pipeline (Phase 11 REL-02) will handle signing + publishing; the sanity-check artifact is intentionally open. Document in Phase 11 if signed releases should replace it.
**Fix:** None required. Consider marking the artifact `retention-days: 7` instead of the default 90 to reduce long-term exposure:
```yaml
- name: Upload Wails app artifact
  uses: actions/upload-artifact@v4
  with:
    name: go-mapi-wails-app
    path: src/app/build/bin/
    retention-days: 7
    if-no-files-found: warn
```

## Not Findings (investigated, dismissed)

These were flagged in the prompt's focus areas and actively checked; no issue found. Documenting so a future reviewer doesn't re-walk the same ground.

- **Stub server lifecycle (focus area 1):** All 17 `httptest.NewServer` call sites in `auth_test.go` and `gmail_test.go` have a matching `defer srv.Close()` (or the equivalent in the `closeServer: true` branch at `gmail_test.go:103-108`). No leaked listeners.
- **Subtests + case tables (focus area 1):** `TestGmailClient_CreateDraft`, `TestBuildFullMIME_Golden`, `TestWatcherDir_EnvPrecedence` all capture loop variables correctly (`tc := tc` at `gmail_test.go:81`, `mime_golden_test.go:156`) and use `t.Run(name, ...)` subtests. `-race`-safe under Go 1.22+ loop-var semantics as well as legacy Go.
- **Shared state between subtests (focus area 1):** `TestWatcherDir_EnvPrecedence` subtests explicitly do NOT use `t.Parallel()` (comment at `paths_test.go:16-17` explains why); `t.Setenv` ensures per-subtest cleanup. Race-free.
- **KeyringStore interface design (focus area 2):** Interface is minimal (3 methods, zero-dep), mirrors `zalando/go-keyring` package-level fn signatures exactly, and `ErrNotFound` semantics are preserved by `fakeKeyringStore.Get` (`auth_test.go:39-50`). `realKeyringStore` is a pure delegator (lines 43-55 of `auth.go`). Clean extraction.
- **Vitest global teardown (focus area 3):** `src/app/frontend/src/test/setup.ts` has `afterEach(vi.clearAllMocks)` and `beforeEach(localStorage.clear)`. Good hygiene. `svelteTesting()` plugin from `@testing-library/svelte/vite` also wires its own autocleanup (per its docs), so component test DOM is cleaned between tests.
- **Svelte 5 runes mounting (focus area 3):** `vitest.config.ts:8` registers `svelteTesting()` explicitly — mandatory for Svelte 5 `mount()` to resolve browser entry instead of SSR entry. All four component tests pass `$props()`-shaped plain objects to `render(Component, { props: {...} })` which is correct for Svelte 5.
- **CI secrets leakage (focus area 4):** No `secrets.*` references anywhere in `build.yml` or `go-race-nightly.yml`. No `GITHUB_TOKEN` overrides. No OAuth client id/secret references. Tests use `httptest` stubs; `wails build` compiles with empty ldflags (D-10 runtime guard triggers `os.Exit(1)` only if the *binary* is executed — `wails build` doesn't execute `main`).
- **`-race` flag scope (focus area 4):** Correctly scoped — `build.yml:86-90` runs `-race` against `./internal/mapi/...` and `./src/app/...` separately (NOT against the C++ interceptor module). `CGO_ENABLED: '1'` is at the job level (`build.yml:58`), required for the race detector on Windows. `go-race-nightly.yml:21, 32` mirrors this.
- **Go/Node version consistency (focus area 4):** `build.yml:66` and `go-race-nightly.yml:29` both pin Go 1.25. `go.work` requires 1.25.0. `package.json` engines.node: >=20.0.0 matches `build.yml:71` (`node-version: 20`). Consistent.
- **Concurrency safety in `app_test.go` (focus area 5):** `TestVisibilityConcurrent` creates 100 goroutines (50 setters + 50 readers) on a freshly-constructed `*App`. All access is through `setVisible` / `isVisible`, both of which lock `a.visibilityMu`. `-race`-safe.
- **MIME boundary regex safety (focus area 6):** `mimeBoundaryRE = regexp.MustCompile('go_mapi_\\d+')` (`mime_golden_test.go:25`) — literal `go_mapi_` followed by `\d+` (1+ digits). The `boundary_collision` test body contains the string `"--go_mapi_PID markers"` (non-digit), which will NOT match. The body itself is base64-encoded in the MIME output, so even a literal digit sequence in the body would be obscured. Future fixtures are safe as long as the regex is not broadened.
