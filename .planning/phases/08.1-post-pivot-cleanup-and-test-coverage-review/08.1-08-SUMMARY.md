## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] Kept workspaces as `["src/app", "src/app/frontend"]` instead of PLAN spec `["src/app"]`**
- **Found during:** Task 1 (workspaces audit per CONTEXT D-22)
- **Issue:** PLAN's acceptance criterion `(.workspaces == ["src/app"])` cannot be satisfied without breaking the frontend workspace lookup. Empirically verified in three permutations:
  - `["src/app"]` → `npm run -w @marcfargas/go-mapi-app-frontend` errors with `No workspaces found`. Frontend cannot be built or tested via the workspace alias.
  - `["src/app"]` + `src/app/package.json` declaring `"workspaces": ["frontend"]` → still errors. npm does NOT honor nested workspaces declared inside a sub-package; only the root `package.json` workspaces array is read.
  - `["src/app", "src/app/frontend"]` → both `@marcfargas/go-mapi-app` (changesets-versioned) and `@marcfargas/go-mapi-app-frontend` (Vite/Vitest target) resolve. Verified `npm run -w @marcfargas/go-mapi-app-frontend build`, `check`, `test:run` all work; verified `npx changeset status` sees both packages.
- **Fix:** Kept `workspaces: ["src/app", "src/app/frontend"]` (the post-Plan-05 Rule-3 deviation state). The PLAN's literal acceptance criterion was empirically infeasible — the prompt's `<parallel_execution>` NOTE ON WORKSPACES explicitly authorized this verification + decision.
- **Files modified:** `package.json`
- **Verification:** `npm run -w @marcfargas/go-mapi-app-frontend build` exits 0; `npx changeset status` reports both packages as candidates for versioning.
- **Committed in:** d365828

**2. [Rule 3 - Blocking] Added `npm run -w @marcfargas/go-mapi-app-frontend build && ` prefix to `check` script**
- **Found during:** Task 1 (PLAN spec for `check` script)
- **Issue:** PLAN spec wrote `"check": "go vet ./internal/mapi/... ./src/app/... && npm run -w @marcfargas/go-mapi-app-frontend check"`. Verified on a clean dist tree (after deleting `src/app/frontend/dist/`): `go vet ./src/app/...` fails with `pattern all:frontend/dist: no matching files found` because `src/app/main.go:12` has `//go:embed all:frontend/dist`. The PLAN itself recognized this exact constraint for the `test` script and prefixed it with the frontend build — same constraint applies to `check`.
- **Fix:** Made `check` script `"npm run -w @marcfargas/go-mapi-app-frontend build && go vet ./internal/mapi/... ./src/app/... && npm run -w @marcfargas/go-mapi-app-frontend check"` (mirrors `test` ordering).
- **Files modified:** `package.json`
- **Verification:** `npm run check` exits 0 on a tree without pre-built `frontend/dist/`.
- **Committed in:** d365828
