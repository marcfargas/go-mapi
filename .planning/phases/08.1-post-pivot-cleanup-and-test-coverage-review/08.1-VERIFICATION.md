### Methodology Notes

Things worth tracking for future phases:

- **Workspaces shape spec-vs-reality mismatch.** The roadmap SC #2 literal `["src/app"]` was empirically infeasible — npm workspaces does not honor nested workspaces declared in `src/app/package.json`. Plans 05 and 08 *both* independently hit this, both logged as Rule-3 Blocking deviations, both kept the pragmatic `["src/app", "src/app/frontend"]`. The CONTEXT D-22 caveat ("planner verifies which nesting npm resolves correctly") acknowledged this risk; future roadmap SCs should avoid committing to a specific npm workspaces-array shape without verifying the nesting model first.
- **`//go:embed all:frontend/dist` build-order coupling.** `src/app/main.go:12` embeds `frontend/dist/` — any `go build`/`go vet`/`go test` on `./src/app/...` requires `npm run -w @marcfargas/go-mapi-app-frontend build` first on a clean checkout. Multiple plans hit this (Plan 01 deferred-items.md, Plan 05 deviation #2, Plan 06 deviation #1, Plan 08 deviation #2). Now encoded into aggregator scripts (`test`, `check`) per Plan 08. CI sequence in `build-wails-app` runs frontend build before any Go work. **Pattern established:** any future plan that touches `src/app/` Go files on a fresh worktree must pre-build the frontend.
- **Executor atomic-commit discipline overrode plan's single-combined-commit design.** Plan 07's Task 3 prescribed one combined commit; executor's parallel-execution context mandated per-task commits. Landed as two commits (`b3e9464` build.yml + `2fa200a` go-race-nightly.yml). No content impact, just commit granularity. Noted in Plan 07 SUMMARY §Methodology adjustments.
- **Plan 04/05 workspaces sequencing.** Plan 04 trimmed workspaces array to `["src/extension", "src/app", "src/app/frontend"]` (dropped only native-host); Plan 05 further trimmed to `["src/app", "src/app/frontend"]` (dropped extension). Plan 08 made final-shape judgment. Clean handoff across waves — each wave preserved the must-hold invariant.
- **Windows ARM64 local dev cannot exercise `-race`.** Plan 03 noted this; QUAL-04 gate relies on `windows-latest` (amd64) in CI for actual race verification. Acceptable per project conventions.
- **Untracked on-disk cleanup.** `src/native-host/`, `src/extension/`, `src/installer/`, `tests/e2e/` still exist on Marc's filesystem as untracked build-artifact leftovers (dist/, node_modules/, build/, compiled `.exe` outputs). They are gitignored and not part of the repository — git-side cleanup is complete. Dev environment can optionally `git clean -fdx` or manually purge to reclaim disk, but this is housekeeping, not a verification gap.
