## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] Workspaces array kept as `['src/app', 'src/app/frontend']` instead of strict `['src/app']`**
- **Found during:** Task 2 (package.json edit)
- **Issue:** Plan 05 Task 2 step 1 specifies `workspaces: ["src/app"]` as the final value, and the plan's `verify` block + `must_haves.truths` enforce this strictly. However, npm workspaces uses literal directory matches (or glob patterns); `["src/app"]` would only register the `src/app/` directory's package.json (`@marcfargas/go-mapi-app`), not the nested `src/app/frontend/` workspace (`@marcfargas/go-mapi-app-frontend`). Task 4's must-hold-invariant verify command — `npm run -w @marcfargas/go-mapi-app-frontend build` — requires the frontend workspace registered. The plan's strict spec contradicts its own must-hold invariant.
- **Fix:** Set workspaces to `["src/app", "src/app/frontend"]` — drops the v2.x extension workspace (the actual goal) and preserves the Wails frontend workspace registration so the must-hold verify can run.
- **Files modified:** `package.json`
- **Verification:** `jq -r '.workspaces | join(",")' package.json` returns `src/app,src/app/frontend`; `npm run -w @marcfargas/go-mapi-app-frontend build` exits 0; `go build ./src/app/... ./internal/mapi/...` exits 0; `go test ./src/app/... ./internal/mapi/...` exits 0.
- **Committed in:** `c315540`

**2. [Rule 3 - Blocking] Frontend rebuild required before `go build` — `src/app/main.go` `go:embed all:frontend/dist` pattern matched zero files**
- **Found during:** Task 4 (must-hold invariant verification)
- **Issue:** First `go build ./src/app/... ./internal/mapi/...` failed with `pattern all:frontend/dist: no matching files found`. The Svelte `dist/` had been wiped by `npm install`'s workspace re-link, and the embed directive requires at least one file present at compile time.
- **Fix:** Ran `npm run -w @marcfargas/go-mapi-app-frontend build` to populate `src/app/frontend/dist/` (2 assets + index.html) before the Go build retry. This is a first-time-build / clean-tree concern, not a code defect; subsequent invocations of the must-hold invariant work in either order.
- **Files modified:** None (build artifact, ignored by git per existing `.gitignore`)
- **Verification:** Second `go build` invocation exited 0; tests pass.
- **Committed in:** N/A (no source change — build-order discipline only)
