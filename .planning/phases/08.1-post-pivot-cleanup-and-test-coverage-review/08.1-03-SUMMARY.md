## Accomplishments

- Refactored `src/app/auth.go` to introduce a `KeyringStore` interface (with `realKeyringStore` and `NewAuthManagerWithStore` test seam). All five package-level `keyring.Get/Set/Delete` call sites now route through the interface; production behavior is byte-for-byte identical on Windows.
- Migrated every existing auth test from the real Windows Credential Manager to an in-memory `fakeKeyringStore` — the `src/app/...` suite now runs green on non-Windows dev machines without a keyring daemon.
- Added `src/app/auth_keyring_windows_test.go` (`//go:build windows`) with real-Credential-Manager round-trip coverage: `TestRealKeyring_WindowsRoundTrip` exercises the `realKeyringStore` directly, and `TestAuthManagerKeyringRoundTrip_RealKeyring` proves the full AuthManager path still works against the actual OS backend on `windows-latest` CI.
- Extended `src/app/auth_test.go` with the eight D-05 gap-fill scenarios: refresh invalid_client / rotated refresh_token / empty access_token, MakeAuthenticatedGmailCall happy path / non-401 bubble, bootstrapAuth transient-error / hard-keyring-error, and fetchUserInfoLocked happy path.
- Created `src/app/app_test.go`, `src/app/paths_test.go`, and `src/app/credentials_check_test.go` — the three currently-zero-coverage glue files now have named tests (NewApp + setVisible/isVisible + concurrent, watcherDir env precedence, credentials guard happy path + both empty branches).

- Converted `userinfoEndpoint` from a `const` to a `var` + getter with `userinfoEndpointOverride` — mirrors the existing `tokenEndpointOverride` / `revokeEndpointOverride` pattern and unblocks the `TestFetchUserInfoLocked_HappyPath` httptest integration.

## Decisions Made

- **`userinfoEndpoint` const → var refactor was added scope (Rule 2).** The plan listed `TestFetchUserInfoLocked_HappyPath` as a required scenario but `userinfoEndpoint` was a `const`, so the existing `tokenEndpointOverride`-style test pattern could not reach it. Converted to a var + getter + override, matching the existing pattern. No production behavior change (override defaults to `""`, getter returns the real Google URL).
- **`TestAuthManagerKeyringRoundTrip` migrated, not duplicated.** The plan specified moving it to the Windows integration file. The cross-platform equivalent (`TestAuthManagerKeyringRoundTrip_Fake`) provides the same coverage against `fakeKeyringStore`, so the two together give the full safety net without double-testing the real keyring.
- **`fakeKeyringStore.getErr` field kept public (package-private).** `TestBootstrapAuth_KeyringGetHardError_SetsErrorState` needs to simulate a non-ErrNotFound error path on `Get`. Rather than introducing a separate fake type or complex setup, the fake carries an optional `getErr` field that short-circuits `Get`. Safe — tests never mutate the field after construction in ways that race.
- **No new dependencies.** Pure stdlib + existing `zalando/go-keyring` + `httptest`. Matches PATTERNS.md Pattern A/B/C/D.
