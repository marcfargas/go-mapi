**2. [Rule 3 - Blocking] Added `svelteTesting()` plugin to vitest.config.ts**
- **Found during:** Task 4 (first run of component tests).
- **Issue:** Svelte 5 runes components failed to mount in jsdom with `Svelte error: lifecycle_function_unavailable — 'mount(...)' is not available on the server`. Module resolution was picking up Svelte's `index-server.js` (SSR entry) instead of the browser bundle, and @testing-library/svelte's `render` calls `mount()` which is client-only in Svelte 5.
- **Fix:** Added `svelteTesting()` plugin from `@testing-library/svelte/vite` to the `plugins` array in `vitest.config.ts`. This plugin handles the browser-vs-server module resolution and wires auto-cleanup — it's the documented @testing-library/svelte v5 Vitest setup per the package README.
- **Files modified:** `src/app/frontend/vitest.config.ts`.
- **Verification:** All 12 failing component tests now pass; 7 total test files / 26 tests pass under `vitest run`.
- **Committed in:** `53f736d` (Task 4 commit, bundled with the component tests it unblocks).
