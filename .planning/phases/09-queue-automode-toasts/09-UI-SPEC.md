## Spacing Scale

Token values already declared in `src/app/frontend/src/lib/styles.css`. Phase 9 extends with two new tokens.

| Token | CSS Variable | Value | Usage |
|-------|-------------|-------|-------|
| xs | `--space-xs` | 4px | Icon-to-text gap (`📎 2`), badge internal padding, focus-outline offset |
| sm | `--space-sm` | 8px | Row vertical padding, button internal gap, badge margin, toggle segment padding |
| md | `--space-md` | 16px | Row horizontal padding, header horizontal padding, section gutter |
| lg | `--space-lg` | 24px | Empty-state block padding, header vertical spacing |
| xl | `--space-xl` | 32px | (new token — add to styles.css) Major layout gap if queue grows a toolbar row |
| 2xl | `--space-2xl` | 48px | (new token — add to styles.css) Reserved for layout-level vertical breaks; not required in Phase 9 UI but added for completeness |

**Add to `styles.css` `:root`:**
```css
--space-xl: 32px;
--space-2xl: 48px;
```

Exceptions:
- Row action buttons: minimum touch/click target height `32px` (desktop WebView2 — mouse-driven; 44px touch-target rule does not apply but 32px floor prevents misclicks)
- Mode-toggle segments: minimum height `28px`, minimum width `72px` per segment
- Error badge: `20px × 20px` circle (not on the 8-point scale — sized to fit `!` glyph at 11px)

## Typography

All sizes are px; weights map to the CSS `font-weight` property.

| Role | Size | Weight | Line Height | CSS |

| Body | 14px | 400 (regular) | 1.5 | `main { font-size: 14px; line-height: 1.5; }` — already set |

Ellipsis truncation: subject column truncates with `overflow: hidden; text-overflow: ellipsis; white-space: nowrap` — already in `.queue-row .subject` in `styles.css`. Extend to the mode-toggle label if it ever wraps.

## Detailed Interaction Contracts

### Queue Row (`QueueRow.svelte`)

**Layout:** CSS Grid, three columns: `[sender 1fr] [subject 2fr] [actions auto]`

Columns match the existing `.queue-row` grid in `styles.css`. Add a fourth implicit cell for the error badge overlaid on the row.

**Row anatomy (left to right):**
1. **Sender** — `font-weight: 600`, truncated at column width. Falls back to `(unknown sender)`.
2. **Subject** — `color: var(--c-text-muted)`, truncated with ellipsis. Falls back to `(no subject)`.
3. **Attachment count** — `📎 N` inline after subject, `font-size: 12px`, `color: var(--c-text-muted)`. **Hidden when count is 0** — no placeholder, no empty span. (Source: D-02)
4. **Timestamp** — `font-size: 12px`, `color: var(--c-text-muted)`, right-aligned. Format: `HH:MM` if today, `MMM D` if earlier. (Existing `formatTimestamp` logic in `App.svelte` — move to a util or keep inline.)
5. **Action buttons** — right-aligned flex pair: `[Create draft] [Dismiss]`. Always visible. (Source: D-01)
6. **Error badge** — `AutoDraftErrorBadge` component, positioned absolutely top-right of the row, visible only when the row has a `failedAutoMode` error state.

**Row states:**
- `idle` — default appearance
- `in-flight` — `Create draft` button shows `Creating…` label, both buttons disabled, opacity 0.7 on the row
- `drafted-flash` — row background transitions to `var(--c-success-flash)`, `✓ Drafted` text appears in subject column, lasts `1.5s`, then the row disappears on next `queue-update` event. CSS: `transition: background-color 300ms ease-in, opacity 300ms ease-out 1.2s` (fade-in green at 0ms, fade-out opacity starts at 1200ms, row gone at 1500ms)
- `error` — row background tints `var(--c-error-bg)`, `AutoDraftErrorBadge` visible, `Create draft` button re-enabled for manual retry
- `disabled-unauthenticated` — both action buttons carry `disabled` attribute + `title="Sign in first"` tooltip (Source: Phase 8 D-07 carried forward)

**Row focus:** `tabindex="0"` on `<li>`, `focus-visible` outline: `2px solid var(--c-accent)`, `outline-offset: -2px`. Row body click is inert (D-03). Tab order: row → `Create draft` button → `Dismiss` button.

**Drafted flash copy:** `✓ Drafted` — 11px semibold, `color: #188038` (Google green — signals success, not in the base token set; add as `--c-success-text: #188038` in `styles.css`).

### Action Buttons

**"Create draft" button:**
- Visual: filled, `background: var(--c-accent)`, `color: white`, `border: none`, `border-radius: 4px`
- Size: `padding: 4px 12px`, min-height `28px`, `font-size: 13px`, `font-weight: 600`
- States: default / hover (`filter: brightness(0.9)`) / disabled (`opacity: 0.5; cursor: not-allowed`)
- Label: `Create draft` (default), `Creating…` (in-flight)

**"Dismiss" button:**
- Visual: ghost/outlined, `background: transparent`, `color: var(--c-destructive)`, `border: 1px solid var(--c-destructive)`, `border-radius: 4px`
- Size: same as Create draft button
- States: default / hover (`background: var(--c-error-bg)`) / disabled (`opacity: 0.5; cursor: not-allowed`)
- Label: `Dismiss` (never changes)
- No confirmation dialog — single-click dismisses immediately. (Source: no destructive confirmation required per D-03; Dismiss is low-stakes — queue JSON just deleted from temp dir)

### AutoDraft Error Badge (`AutoDraftErrorBadge.svelte`)

- Shape: `20px × 20px` circle, `background: var(--c-destructive)`, `color: white`
- Content: `!` at 11px semibold, vertically and horizontally centered
- Position: `position: absolute; top: 6px; right: 6px` within the row (row must be `position: relative`)
- Tooltip: native `title` attribute showing error category string (see Copywriting Contract). On keyboard focus of the badge, `aria-describedby` to a visually-hidden `<span>` with the same text.
- Keyboard: `tabindex="0"`, role="status"

### Mode Toggle (`ModeToggle.svelte`)

**Visual:** Two-segment pill — not a toggle switch, not radio buttons. Matches Windows Segmented Button pattern.

```
┌──────────────┬───────────────┐
│   Manual     │  Auto-draft   │
└──────────────┴───────────────┘
  active (filled)  inactive (ghost)
```

- Container: `display: inline-flex`, `border: 1px solid var(--c-border)`, `border-radius: 4px`, `overflow: hidden`
- Active segment: `background: var(--c-accent)`, `color: white`, `font-weight: 600`, `font-size: 13px`
- Inactive segment: `background: var(--c-surface-alt)`, `color: var(--c-text)`, `font-weight: 400`, `font-size: 13px`
- Each segment: `padding: 4px 16px`, min-height `28px`, min-width `72px`, `border: none`, `cursor: pointer`
- Active segment hover: no change (already selected)
- Inactive segment hover: `background: var(--c-border)`
- Focus-visible on each segment: `outline: 2px solid var(--c-accent); outline-offset: -2px`
- Segment labels: `Manual` / `Auto-draft` (sentence case, English)
- Placement: right side of `SignedInHeader` flex row, separated from sign-out button by `var(--space-md)` gap
- Only rendered when `auth.authenticated === true`
- `aria-pressed="true"` on the active segment; `role="group"` + `aria-label="Draft mode"` on the container

## Toast Visual Contract (Go-side, not Svelte)

The toast XML is generated in Go (not in the Svelte frontend). This section specifies the content schema so the Go implementation matches the UX contract.

**Arrival toast schema:**
```xml
<toast launch="action=open&amp;emailId={id}">
  <visual>
    <binding template="ToastGeneric">
      <text>{sender display name}</text>
      <text>{subject}</text>
      <!-- Only when attachment count > 0: -->
      <text>📎 {N} attachment(s)</text>
    </binding>
  </visual>
  <actions>
    <action content="Create draft" arguments="action=create-draft&amp;emailId={id}" activationType="foreground"/>
    <action content="Dismiss" arguments="action=dismiss&amp;emailId={id}" activationType="foreground"/>
  </actions>
</toast>
```

**Toast activation:** `activationType="foreground"` — brings app window to foreground, Go handles the action, window re-hides. (Source: D-07 — foreground-activation path chosen; COM background activator deferred to Phase 10 if needed. RDS validation: foreground-activation works per-session in RDS since each session has its own desktop and window station. HKCU AUMID registration is per-user, RDS-safe.)

**Tag/group scheme (NOTIF-05):**
- `tag` = email content-hash ID (64-char hex from `EmailWatcher`)
- `group` = `"go-mapi-queue"`
- On draft success or dismiss: call `ToastNotifier.History.Remove(tag, group, aumid)`

**Arrival toast suppression rule (D-11):**
- Suppress when: main window is visible AND focused
- Always fire: error toasts (regardless of window state)
- Draft-success toast: same suppression rule as arrival — window visible → in-window flash only

**Draft-success toast schema (window hidden):**
```xml
<toast>
  <visual>
    <binding template="ToastGeneric">
      <text>Draft created: {subject}</text>
    </binding>
  </visual>
  <!-- No action buttons — dismissible only -->
</toast>
```

## Tray Icon Variants

Three static `.ico` assets. All must exist at `src/app/assets/tray/` and be embedded via `//go:embed`.

| File | State | Visual suggestion |
|------|-------|------------------|
| `tray-idle.ico` | No queue, signed in, watching | Existing icon (envelope outline or go-mapi glyph) |
| `tray-has-queue.ico` | Queue has ≥ 1 pending email | Same base glyph with filled orange/amber dot bottom-right at 16×16. Suggested: `#E8A600` dot (Windows amber — high visibility, not error red). Both 16×16 and 32×32 frames in the `.ico` |
| `tray-error.ico` | Watcher stopped or fatal error | Existing icon (if already has error variant) |

**Priority (highest wins when multiple states apply):**
1. `tray-error` — watcher stopped
2. `tray-has-queue` — signed in, ≥ 1 pending
3. `tray-idle` — signed in, queue empty, paused, or signed out

Paused and signed-out states are tooltip-only — no distinct icon variant. (Source: D-16.)

**ICO format:** Both 16×16 and 32×32 frames within each `.ico` file for HiDPI/RDS compatibility. (Source: CONTEXT.md §Claude's Discretion — Phase 9 ships what RDS needs; RDS sessions typically run at 96 DPI but having 32×32 available prevents blurry scaling on higher-DPI remote sessions.)

## Accessibility Baseline

- All interactive elements reachable by `Tab`; action buttons have explicit `type="button"`
- Focus order within a row: row container (`tabindex="0"`) → `Create draft` button → `Dismiss` button → error badge (if visible)
- `aria-label="Draft mode"` + `role="group"` on ModeToggle container
- `aria-pressed="true/false"` on each toggle segment
- `aria-live="polite"` region wrapping the queue `<ul>` — screen reader announces additions without interrupting
- Error badge: `role="status"` + `aria-label="Auto-draft failed: {errorCategory}"`
- `ReAuthBanner`: already has `role="alert"` — no change needed
- Drafted-flash: announce `✓ Drafted` via `aria-live="assertive"` region (brief inline announcement); the flash itself is decorative color
