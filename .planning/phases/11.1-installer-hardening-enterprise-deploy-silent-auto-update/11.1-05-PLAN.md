<threat_model>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Installer (admin elevation) → Task Scheduler service | The installer registers a SYSTEM-context task. UAC elevation is mandatory (RequestExecutionLevel admin baseline + admin install path D-01); admin user is the trusted boundary. |
| Task Scheduler service → go-mapi.exe (SYSTEM) | OS triggers go-mapi.exe with --update-check-silent under SYSTEM. Task XML is stored at `%SystemRoot%\System32\Tasks\go-mapi Auto Update` (only SYSTEM + Administrators writable). |
| Uninstaller → Task Scheduler service | Idempotent task removal; no privilege escalation surface. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-11.1.05-01 | Elevation of Privilege | Attacker writes to %ProgramData%\go-mapi\updates\staging\ between download and SYSTEM task pickup, causing SYSTEM RCE | mitigate | %ProgramData% default DACL gives Users read-only; non-admin users cannot tamper. Plan 11.1-04's verify-BEFORE-swap pattern means even if a malicious staged file exists, ChecksumValidator rejects unless the manifest is also forged. |
| T-11.1.05-02 | Tampering | Attacker writes to `%SystemRoot%\System32\Tasks\go-mapi Auto Update` to swap the action | mitigate | Tasks dir is admin-only (NTFS ACL inherited from %SystemRoot%); pre-existing admin compromise is out of scope of any defense. Standard Windows trust assumption. |
| T-11.1.05-03 | Injection | `/AUTOUPDATE=" malicious"` (with embedded text) parsed by NSIS GetOptions could leak into command construction | mitigate | NSIS `${GetOptions}` returns the raw post-`=` value as a string. The .nsi compares only via `StrCmp $AutoUpdateFlag "1"` — strict bool. Anything other than the literal "1" is treated as OFF. The value never flows into `ExecWait` argument construction (only the literal `schtasks /create /XML "$INSTDIR\go-mapi-auto-update.xml" ...` line uses fixed strings). |
| T-11.1.05-04 | Tampering | INSTDIR_PLACEHOLDER substitution via PowerShell could be exploited if $INSTDIR contains shell metacharacters | mitigate | The substitution uses `[regex]::Escape($INSTDIR)` on the replacement value — escapes any regex meta. The `Set-Content` writes to a fixed path. NSIS-side $INSTDIR is constrained by the installer page and is always under %ProgramFiles% in admin install — no user-controlled path injection. |
| T-11.1.05-05 | Spoofing | An attacker who has admin elevation creates a task with the same name `\go-mapi Auto Update` pointing at a malicious binary | accept | Pre-existing admin compromise. Same trust boundary as creating any other malicious system service. Out of scope. |
| T-11.1.05-06 | Information Disclosure | Task XML stored at System32\Tasks\go-mapi Auto Update is world-readable | accept | Task XML contains no secrets — just the install path + flag. Standard practice; same as every other Scheduled Task on Windows. |
| T-11.1.05-07 | DoS | Uninstaller hangs because schtasks /delete blocks waiting for a running task | mitigate | `MultipleInstancesPolicy=IgnoreNew` plus `AllowHardTerminate=true` in the XML means a running task instance can be terminated. `/F` flag on `schtasks /delete` forces removal without confirmation. ExecWait with no timeout could in theory hang, but `schtasks` itself returns within seconds even on a running task. |
