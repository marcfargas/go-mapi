# Audit: Release Pipeline Assets + DLL Build Paths (11.1-03)

**Date:** 2026-04-25
**Scope:** .github/workflows/installer-release.yml

## 1. Current Asset Audit

The existing `installer-release.yml` produces the following artifacts on the `windows-latest` runner:

| Asset | Workflow Source Path (Local) | Published Name (GitHub Release) |
|-------|------------------------------|---------------------------------|
| Installer | `${{ steps.final.outputs.path }}` | `go-mapi-setup.exe` |
| Wails App | `src/app/build/bin/go-mapi.exe` | n/a (contained in installer) |
| Interceptor (x64) | `src/interceptor/build-x64/bin/go-mapi.dll` | n/a (contained in installer) |
| Interceptor (x86) | `src/interceptor/build-x86/bin/go-mapi.dll` | n/a (contained in installer) |

**Note on DLL paths:** The current `installer-release.yml` contains a path mismatch error in the `Stage unsigned binaries` and `Replace staged binaries with signed versions` steps. It references `src/interceptor/build/bin/go-mapi.dll`, which does not exist. `src/interceptor/build.ps1` produces `build-x64` and `build-x86` subdirectories.

## 2. Decision: Option A (Full Manifest)

**Selected:** **Option A** (Include all four binaries in `SHA256SUMS.txt`).

**Rationale:** 
- The interceptor build already produces both x64 and x86 bitnesses.
- Including individual binaries in the manifest enables future silent-updater strategies that can swap individual files (e.g., via `MoveFileEx`) rather than re-running the full installer, even if Plan 11.1-04 initially uses the installer-relaunch strategy.
- Consistency with the `sha256sum` convention used by other projects (goreleaser, etc.).

## 3. Implementation Plan

### 3.1 Correcting SignPath Staging
To support Option A and ensure the installer contains signed binaries when SignPath is active, the staging steps must be corrected to use the real build paths:

- **Stage:**
  - `src/app/build/bin/go-mapi.exe` -> `staged/go-mapi.exe`
  - `src/interceptor/build-x64/bin/go-mapi.dll` -> `staged/go-mapi-x64.dll`
  - `src/interceptor/build-x86/bin/go-mapi.dll` -> `staged/go-mapi-x86.dll`
- **Restore:**
  - `staged-signed/go-mapi.exe` -> `src/app/build/bin/go-mapi.exe`
  - `staged-signed/go-mapi-x64.dll` -> `src/interceptor/build-x64/bin/go-mapi.dll`
  - `staged-signed/go-mapi-x86.dll` -> `src/interceptor/build-x86/bin/go-mapi.dll`

### 3.2 Manifest Generation
The new "Generate SHA256SUMS.txt" step will be inserted after the `id: final` step (approx. line 168) and before the "Attach installer to GitHub Release" step.

**Asset List for SHA256SUMS.txt:**
- `go-mapi-setup.exe` (from `${{ steps.final.outputs.path }}`)
- `go-mapi.exe` (from `src/app/build/bin/go-mapi.exe`)
- `go-mapi-x64.dll` (from `src/interceptor/build-x64/bin/go-mapi.dll`)
- `go-mapi-x86.dll` (from `src/interceptor/build-x86/bin/go-mapi.dll`)

### 3.3 GitHub Release Update
The `softprops/action-gh-release@v2` step's `files:` block will be updated to:
```yaml
files: |
  ${{ steps.final.outputs.path }}
  SHA256SUMS.txt
```
