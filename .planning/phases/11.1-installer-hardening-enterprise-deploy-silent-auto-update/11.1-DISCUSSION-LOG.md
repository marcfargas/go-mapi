## Silent-update worker architecture

| Option | Description | Selected |
|--------|-------------|----------|
| Windows Scheduled Task under SYSTEM | `schtasks /create /RU SYSTEM /RL HIGHEST`; no service installation; standard pattern | ✓ |
| Dedicated Windows Service | Persistent background service; more plumbing; SCM install + uninstall | |
| In-process goroutine running as SYSTEM | Rejected — Wails app runs under the interactive user, no SYSTEM privs | |

**User's choice:** Scheduled Task under SYSTEM. "In-process won't work (user privs); we need system scheduled task (better than service)."
**Notes:** Matches enterprise-friendly convention; installer + uninstaller manage the task idempotently via `schtasks`.

### Swap strategy

| Option | Description | Selected |
|--------|-------------|----------|
| `MOVEFILE_DELAY_UNTIL_REBOOT` | Stage binary, let Windows swap at next boot | |
| Atomic `MoveFileEx` with rename-while-running trick | Rename running EXE → `.old.<pid>`, write new binary into original path | ✓ |
| WM_CLOSE the running app first, then swap | Surprise shutdown for the user mid-action | |

**User's choice:** Atomic swap. "Atomic swap seems the least disruptive." Plus: "RDS environments that won't reboot, the updater should stick around until it can get a lock and then swap the file, and no concurrent task runs."
**Notes:** Explicitly rejects reboot-delayed swap — RDS hosts don't reboot, which would leave updates pending forever. Updater retries with backoff until the swap lands. `MultipleInstancesPolicy = IgnoreNew` on the Scheduled Task prevents overlapping runs.

## Installer hardening — T4 32-bit DLL reinstall fix

| Option | Description | Selected |
|--------|-------------|----------|
| Drop 32-bit DLL support | Remove x86 build, install x64 DLL only | |
| Pragmatic patch-around | Blanket `SetOverwrite try` + pre-delete, ship without root-cause | |
| Root-cause investigation + minimal fix + Pester regression | Repro VM spike, identify actual cause, apply targeted fix, lock with test | ✓ |

**User's choice:** Root-cause + fix. "We can't drop 32-bit support."
**Notes:** Legacy MAPI callers compiled i686 need the x86 DLL. Planner spikes the repro (UAC file-virtualisation? NSIS `SetOverwrite` block drift? AV scan hold?) then applies the minimal fix. Pester regression locks reinstall-over-existing.

## Hash source

| Option | Description | Selected |
|--------|-------------|----------|
| `SHA256SUMS.txt` alongside assets at `latest/download/` | goreleaser-style manifest, matches `creativeprojects/go-selfupdate` convention | ✓ |
| Per-asset digest from GitHub Releases metadata API | Requires `gh api` call + token | |
| Authenticode signature verification | Blocks unsigned beta/dev releases | |

**User's choice:** SHA256SUMS alongside artefacts. "The sums with the artifacts is the right and common place." Explicitly rejected Authenticode: "We have no signature now and that would break beta releases too, we can verify the hash though which does not require signature."
**Notes:** Hash verification is the integrity primitive. Authenticode deferred until every release reliably ships SignPath-signed.

## Swap-while-running conflict handling

| Option | Description | Selected |
|--------|-------------|----------|
| `MOVEFILE_DELAY_UNTIL_REBOOT` — swap at next boot | Fails for RDS hosts that don't reboot | |
| Retry with backoff until file lock releases | Updater sticks around; no concurrent runs allowed | ✓ |
| WM_CLOSE the running app first | Surprises user mid-action | |

**User's choice:** Retry + stick around. RDS context explicitly drove the decision.
**Notes:** `MultipleInstancesPolicy = IgnoreNew` + retry cap (planner decides, candidate 12h or until next trigger) prevents SYSTEM process accumulation. Rename-while-running trick expected to succeed in most cases even with the app running.

## Claude's Discretion

- Exact NSIS UI primitive for the "Enable automatic updates" checkbox (components page vs. FinishPage vs. dedicated page).
- Exact daily-jitter primitive (`schtasks /RI /DU` vs. XML `<RandomDelay>`).
- Pester Describe/Context/It naming for new D-18 coverage.
- Whether `--update-check-silent` is a top-level CLI flag vs. a hidden Wails mode flag (must respect Phase 7 single-instance mutex).
- Retry cadence + cap inside the silent updater (D-14 planner decision).
- `SHA256SUMS.txt` generation primitive (`sha256sum` via Git Bash vs. `Get-FileHash` vs. goreleaser-style).
- Exact staging path + cleanup semantics for `%ProgramData%\go-mapi\updates\`.

## Deferred Ideas

- Machine-wide config YAML (`go-mapi.machine.yaml`) + user-layer (`go-mapi.user.yaml`) + `.example` files + `locked:` keys + `schema_version`.
- Tri-state install choice (collapsed to binary; Notify is the floor).
- Authenticode signature verification on downloaded binaries.
- Wails UI for silent-update status or admin-locked indicators.
- Enumerate-all-profiles uninstall scrub (Phase 10 D-19 limitation carried forward).
- Migration helper for v3.0 GA users to enable silent update post-install (re-run `go-mapi-setup.exe /AUTOUPDATE=1` for now).
