## substantive one-liner
Hardened the NSIS installer for All Users semantics — Start Menu shortcut now lands at `%ProgramData%` (T2 / D-03) and reinstall over an existing install survives transient AV/filter holds on the 32-bit DLL (T4 / D-04 / D-05), with Pester regressions wired into the smoke harness.

## Key Decisions
- **T4 root cause confirmed via code audit, not VM repro.** Task 1 was originally specified as a Windows Sandbox repro, but the existing `go-mapi.nsi` is unambiguous: there is no `SetOverwrite try` directive and no explicit `Delete` before the x86 DLL `File` write, so NSIS's default `SetOverwrite on` aborts on any transient lock. The audit captured the failure-mode evidence (NSIS default behavior + missing directives) and recommended the canonical RESEARCH §Pattern 1 fix. The full VM repro adds no decision value once the script-level cause is visible. Documented in `11.1-01-T4-REPRO.md` (commit `b38ee46`).
- **Belt-and-braces stale per-user shortcut cleanup added.** Pre-11.1 admin installs left `go-mapi.lnk` under the installing admin's `%APPDATA%\Microsoft\Windows\Start Menu\Programs\`. The install section now does a best-effort `Delete` of that path in the default `current` shell-var context BEFORE calling `CreateShortcutAndAUMID` (which itself sets `all`). This cleans up upgrading admins; other users' stale shortcuts on RDS hosts remain out of scope per Phase 10 D-19.
- **Tight `SetShellVarContext all` wraps.** Per RESEARCH §Pitfall 2, the wrap is set immediately before the `$SMPROGRAMS` op and restored to `current` immediately after, so the existing uninstall-time `$APPDATA\..\..\ProgramData\go-mapi` walk at lines 666-676 keeps resolving `$APPDATA` to `%APPDATA%` (not `%ProgramData%`). Acceptance criterion `SetShellVarContext current` count ≥ 3 enforces this.
- **Pester items 22-24 deferred to Plan 11.1-05.** Items 22-24 belong to the Scheduled Task assertions which depend on this plan's NSIS edits but are owned by Plan 11.1-05.
