## substantive one-liner
Laid down the Go scaffolding for the silent auto-update path — `--update-check-silent` flag at the top of `main()`, `updatesStagingDir()` env-precedence helper, `runSilentUpdate(ctx)` entry stub with build-tag split, and unit tests for flag parsing, paths, and the no-update / update-available / fetcher-error / log-truncation paths.

## Key Decisions
- **Build-tag split for the silent path.** `updates_silent.go` is `//go:build windows && !bindings`; `updates_silent_bindings.go` is `//go:build bindings` and stubs `runSilentUpdate` to a no-op. This mirrors Phase 8's `credentials_check.go` pattern (D-09) and ensures `wailsbindings.exe` introspection cannot trigger `os.Exit` from within the silent path. RESEARCH §Pitfall 7.
- **Env-precedence for the staging directory.** `updatesStagingDir()` follows the existing `appDataDir()` / `watcherDir()` idiom: honor `GOMAPI_UPDATES_DIR` if non-empty, else `%ProgramData%\go-mapi\updates\`, else fall back to the per-user `%LOCALAPPDATA%\go-mapi\updates\`. The override exists for tests; production uses ProgramData (SYSTEM-writable in session 0).
- **Scaffold-only — no real download yet.** Plan 11.1-04 owns the actual download + ChecksumValidator + `MoveFileEx` atomic swap. This plan ships only the entry path, the staging-dir helper, the build-tag split, the binding stub, and the unit tests. The CheckNow happy-path stub logs `update available: latest=X — download/verify/swap deferred to Plan 11.1-04`.
- **Flag-parse position.** `--update-check-silent` is checked at the very top of `main()`, before `acquireSingleInstance` and any Wails init. This guarantees the silent path never spawns the tray, the WebView2 host, or the keyring.

The targeted silent-update test runs (without `-race`) all pass, and both build configs (default + `bindings`) compile cleanly. CI's existing `build-wails-app` job is the authoritative gate.
