# Phase 11.1: Installer hardening + enterprise deploy + silent auto-update - Context

**Gathered:** 2026-04-24
**Status:** Ready for planning

<domain>
## Phase Boundary

Ship v3.0 with the enterprise-deploy story the initial Phase 11 release missed, scoped tightly:

1. **Installer is unconditionally All Users.** `RequestExecutionLevel admin` is already enforced; Phase 11.1 drops every lingering "Current User" path, caveat, and docs reference, and corrects the `SetShellVarContext` bug that pushed the Start Menu shortcut into `%APPDATA%\...` instead of `%ProgramData%\...` (todo T2).
2. **T4: 32-bit `go-mapi.dll` reinstall-overwrite bug is root-caused and fixed** with a Pester regression. Dropping 32-bit support is not an option — legacy MAPI callers depend on it.
3. **Silent auto-update as an install-time opt-in.** A single "Enable automatic updates" checkbox (default OFF, also settable via `/AUTOUPDATE=1` on the command line). When checked, the installer registers a Windows Scheduled Task under `SYSTEM` that downloads + hash-verifies + atomically swaps the new binaries without elevating the interactive user. When unchecked, Phase 11's notify-only UX stays as the floor.
4. **CI + README refresh** covering the All Users caveat, the `/AUTOUPDATE=1` parameter, how to manage the Scheduled Task post-install, and the SHA-256 verification expectation.

**Out of scope for Phase 11.1 (deferred):**

- **Machine-wide config YAML surface** (`%PROGRAMDATA%\go-mapi\go-mapi.machine.yaml`, user-layer override, `locked:` keys, `schema_version`, example files). The silent-update path does not need a config gate — the install-time checkbox is the gate. Revisit at v3.1+ when an actual control-plane / MDM story emerges.
- **Tri-state "None / Notify / Silent"** install-time choice (originally framed in the ROADMAP). Collapsed to a binary checkbox because Notify is already always-on from Phase 11.
- **Authenticode signature verification** on downloaded binaries. Deferred until every release is reliably SignPath-signed (unsigned beta/dev builds would break today). Hash verification covers integrity.
- **Wails UI for the update-mode toggle or "locked by admin" indicators.** No in-app UI changes in Phase 11.1. Manual "Check for updates now" (already in tray from Phase 11) stays unchanged.
- **Multi-user RDS per-user scrub on uninstall.** Limitation carried forward from Phase 10 D-19.
- **Phase 11's paused 11-04 Task 2+3** (store delisting + GA tag push). Still gated on `go-mapi-www` per STATE.md; explicitly non-blocking and untouched here.

<decisions>
## Implementation Decisions

### Scope + boundary
- **D-01:** Installer is **unconditionally All Users**. No per-user install path, no scope toggle, no fallback. UAC elevation mandatory. All NSIS files, README copy, and in-repo docs scrub any "Current User" language. Rationale: MAPI handler registration is inherently machine-wide via `HKLM\SOFTWARE\Clients\Mail\`; a per-user install path is meaningless for the core feature.
- **D-02:** Machine-wide YAML config surface + `.example` files + `locked:` key semantics — **deferred entirely, not in Phase 11.1 scope**. Once silent-update is gated only by the installer checkbox (D-07/D-08), no config gate is needed for this phase.

### T2 — Start Menu shortcut under All Users (`SetShellVarContext all`)
- **D-03:** Wrap `CreateShortcutAndAUMID` (install) and the matching `Delete "$SMPROGRAMS\go-mapi.lnk"` (uninstall) with `SetShellVarContext all` so `$SMPROGRAMS` resolves to `%ProgramData%\Microsoft\Windows\Start Menu\Programs\` for every user — not just the admin who ran the installer. The existing comment at `src/installer/go-mapi.nsi:573-574` already claims this behavior; Phase 11.1 makes the claim true. Matches Phase 10 D-13's original intent. Harness fix at `tests/sandbox/phase11/Run-Phase11Smoke.ps1 Launch-App` already tolerates both locations — the real fix lives in NSIS.

### T4 — 32-bit `go-mapi.dll` reinstall-overwrite fix
- **D-04:** Root-cause investigation is **mandatory** — Phase 11.1 does not ship a pragmatic patch-around (e.g. blanket `SetOverwrite try` + pre-delete) without first identifying the real cause. Candidate hypotheses to probe on a repro VM: NSIS `SetOverwrite` default inside the x86 `SetOutPath "$PROGRAMFILES32\go-mapi"` block diverging from the x64 block; UAC file-virtualisation ACL drift on a DLL originally written by an unelevated predecessor; Defender real-time scan transient hold; async uninstall-sub-step race against overwrite. The todo at `.planning/todos/pending/2026-04-23-installer-overwrite-locked-32bit-dll.md` rules out kernel image-locking (manual elevated delete succeeds) and a simple running-process lock (already guarded). Planner spikes the repro, root-causes, applies the minimal fix.
- **D-05:** Pester regression test in `src/installer/tests/installer.Tests.ps1` covering: fresh install → reinstall-over-existing without a manual uninstall → verify both x64 + x86 DLLs overwrite cleanly and registry DLLPath values still point correctly in both registry views. Blocking gate in `installer-smoke.yml`.
- **D-06:** Dropping 32-bit DLL support is **off the table**. Legacy MAPI callers (Win32 apps compiled i686) require the x86 DLL; removing it regresses the core bridge feature.

### Silent auto-update — install-time opt-in
- **D-07:** NSIS installer exposes a single **boolean** "Enable automatic updates" affordance (a ModernUI2 components-page checkbox or a dedicated FinishPage option — planner picks the most discoverable). **Default OFF.** Silent-install parameter `/AUTOUPDATE=1` force-enables from the command line for fleet provisioning. No tri-state, no "None / Notify / Silent" menu — Notify is already always-on from Phase 11 and is the floor for all users.
- **D-08:** When enabled, installer registers a Windows Scheduled Task named **`go-mapi Auto Update`** running under the `SYSTEM` account with:
  - `MultipleInstancesPolicy = IgnoreNew` — no concurrent runs (prevents overlapping download/swap races).
  - `RunOnlyIfNetworkAvailable = true`.
  - `StartWhenAvailable = true` — catches machines that were off at the scheduled time.
- **D-09:** Trigger schedule: **daily at 03:00 with ±30min jitter** (avoids fleet-wide thundering herd against GitHub Releases) **+ at-startup catch-up** (covers RDS / desktop boxes powered off overnight). No logon trigger — that couples updates to user activity, which is the pattern we're escaping.
- **D-10:** Task action: **self-invoke `go-mapi.exe --update-check-silent`** (new CLI flag on the Wails binary). Reuses the existing `src/app/updates.go` fetch + version-compare code path established in Phase 11 — only the outcome diverges (download + verify + swap instead of emit toast). A separate helper binary was considered and rejected: one code path is simpler and keeps the updater logic in one place.
- **D-11:** Download integrity: the release pipeline publishes **`SHA256SUMS.txt`** alongside `go-mapi-setup.exe` and `go-mapi.exe` at the stable `https://github.com/marcfargas/go-mapi/releases/latest/download/` URL. The silent task fetches the manifest first, downloads the installer/binary, verifies the SHA-256 digest, then swaps. No Authenticode verification in Phase 11.1 — would break unsigned beta/dev releases where SignPath is skipped. Matches `creativeprojects/go-selfupdate` native convention.
- **D-12:** Swap strategy: stage download at `%ProgramData%\go-mapi\updates\`, verify hash, then use Windows' atomic `MoveFileEx` "rename-while-running" trick to swap the installed binary. **`MOVEFILE_DELAY_UNTIL_REBOOT` is explicitly rejected** — primary deployment target includes RDS servers that do not reboot. If the swap attempt fails because the file is in use, the updater **retries with backoff and sticks around until the swap succeeds** (up to a cap — see D-14).
- **D-13:** The silent updater **does NOT** `WM_CLOSE` the running `go-mapi.exe`. User is not surprised mid-action. The retry loop is the backpressure mechanism — next natural idle moment, the swap lands.
- **D-14:** Retry cap for the sticking-around updater: planner decides during implementation (candidate: 12 hours or until the next scheduled trigger fires, whichever comes first). No indefinite loop that accumulates a permanent SYSTEM-scoped process. `MultipleInstancesPolicy = IgnoreNew` from D-08 ensures the next trigger is a no-op while the current one is still retrying.

### Frontend UX
- **D-15:** **No Wails UI changes in Phase 11.1.** The install-time checkbox is the sole auto-update affordance. Phase 11's tray "Check for updates now" manual path stays unchanged and remains available whether auto-update is on or off. No "admin-locked" tooltip, no settings screen for auto-update mode, no toggle. Admins who want to flip silent-update post-install manage the Scheduled Task directly (Task Scheduler UI or `schtasks /change /tn "go-mapi Auto Update" /disable|/enable`).

### Uninstaller
- **D-16:** Uninstaller **idempotently removes the Scheduled Task** in all cases, whether or not the installer created one: `schtasks /delete /tn "go-mapi Auto Update" /f`. "Task not found" exit code is swallowed. Runs before the binary + `$INSTDIR` scrub so the task cannot fire mid-uninstall.

### Release pipeline + CI
- **D-17:** `.github/workflows/installer-release.yml` extended to generate + publish `SHA256SUMS.txt` alongside the existing release assets. Hash algorithm: **SHA-256** (matches `creativeprojects/go-selfupdate` convention). Manifest format: one line per asset, standard `<hex-digest>  <filename>` layout. SignPath gating unchanged — SHA-256 is additive, never replaces signing when signing is available.
- **D-18:** `installer-smoke.yml` Pester coverage extended with:
  1. Fresh install with `/AUTOUPDATE=0` → verify no Scheduled Task exists.
  2. Fresh install with `/AUTOUPDATE=1` → verify Scheduled Task `go-mapi Auto Update` exists with correct principal (`SYSTEM`), triggers, and `MultipleInstancesPolicy`.
  3. **32-bit DLL overwrite regression** (D-05): install → install again without uninstall → both DLLs overwrite cleanly.
  4. **Shortcut lands in `%ProgramData%`** (D-03 regression): install → verify `%ProgramData%\Microsoft\Windows\Start Menu\Programs\go-mapi.lnk` exists and `%APPDATA%\...\go-mapi.lnk` does not.
  5. Uninstaller removes the Scheduled Task (D-16) even when it was not created (/AUTOUPDATE=0 path — uninstall still exits clean).
  6. Uninstaller removes `%ProgramData%\go-mapi\` residue (updates staging dir + existing `uninst\` dir).

### Documentation + ROADMAP
- **D-19:** `README.md` gains an "Enterprise installation" section covering: All Users elevation requirement (no per-user path), `/AUTOUPDATE=1` silent-install parameter, behavior of the `go-mapi Auto Update` Scheduled Task + how to manage it post-install, SHA-256 integrity verification expectation, multi-user RDS caveat (carry-forward from Phase 10 D-19). <specifics>
## Specific Ideas

- **`SHA256SUMS.txt` format:** one asset per line, `<64-char hex digest>  <filename>` (two spaces, matches `sha256sum` output). Scheduled task parser is trivial regex/split.
- **Scheduled Task naming:** `go-mapi Auto Update` (with the product-name space for discoverability in Task Scheduler UI). Not `gomapi-autoupdate` or similar terse names.
- **Scheduled Task path:** root of Task Scheduler (`\go-mapi Auto Update`), not nested under a `\go-mapi\` folder — simplifies `schtasks` invocation and uninstall cleanup.
- **`/AUTOUPDATE=N` syntax:** NSIS standard convention parses `/NAME=value`; choose `1`/`0` so CI scripts can pass `/AUTOUPDATE=1` unambiguously.
- **Rename-while-running trick:** `MoveFileEx(installed, installed + ".old.<pid>", MOVEFILE_REPLACE_EXISTING)` → `MoveFileEx(staged, installed, 0)`. Windows permits renaming a running EXE (NTFS semantics); deletion of the `.old` orphan is deferred to next uninstall or task cleanup.
- **Retry backoff sketch:** 30s initial, exponential to 5min cap, total wall-clock cap per D-14 (12h or next trigger). Persist `last-attempted-hash` across retries so repeated download isn't needed between swap attempts.
- **Jitter primitive:** `schtasks` supports `/RI` (repetition interval) + `/DU` (duration) but not native random-delay; use the XML task definition with `<RandomDelay>PT30M</RandomDelay>` for the daily trigger.
- **Task principal:** `/RU SYSTEM /RL HIGHEST` via `schtasks /create`. No service account, no credential prompt at install time.
- **Single-instance collision:** the silent updater runs as SYSTEM, the interactive app runs as the logged-in user — separate sessions, the Phase 7 named mutex likely does not collide. Planner verifies on a multi-session RDS box.

</specifics>
