# Capture go-mapi material

Resolve the checkout, original request, readers, sources and write scope. Retrieval
and report-only requests stay read-only. Recording a proposal neither approves nor
executes it. Complete supported capture here; do not route the same payload back
to a shared router or invoke a maker.

## Select the existing home

Follow an explicit reference first. Otherwise use scoped `rg --files`, `rg -n`
and `Get-Content -LiteralPath` to find relevant repository or selected task-folder
coverage. For work records, search the selected GitHub repository including closed
issues using the [provider operations](references/discovery.md). Read sources and
linked records; local history cannot establish tracker-wide deduplication. Decide
whether to reuse, materially update, create or make no write before drafting.

- Lasting technical knowledge belongs in an existing README, DEVELOPMENT.md or
  `docs/` home. Pass the selected home, sources and uncertainty directly to
  [go-mapi-docs](../go-mapi-docs/SKILL.md), which completes that operation.
- Provisional designs, reviews and resumable work use the supplied task folder
  or available **mafe-si:owner-paths**. Without it, use
  `$env:LOCALAPPDATA/agent-work/retained/go-mapi/<task>` outside the repository;
  verify LOCALAPPDATA rather than guessing a profile or falling back into source.
- Shared actionable requests and unfinished outcomes use GitHub issues in
  `marcfargas/go-mapi`, selected by the owner. Retain substantive work needing
  durable follow-through early, with open decisions and manageable pieces where
  useful. A tracker binding, edit, review or check alone requires no new issue:
  bounded maintenance already covered by the conversation or PR can stay there.
  Honor explicit capture and detailed-discussion requests; reassess if a genuine
  follow-through need emerges. Do not create retrospective tickets for completed
  session work or invent labels, hierarchy, queues or private configuration.
- When no durable write is needed or permitted, return the useful result here.
  A requested draft must remain distinguishable from retained material.

Preserve explicit capture requests and independently useful obligations. If
shared tracking is required but unresolved, retain the original request, source,
remaining decision and next actor in the handback; an authorized local draft can
support it but cannot substitute for the required tracker record. Only the
tracker-dependent operation stops; continue independent authorized work.

Before provider writes, distinguish local retention from a proposed or authorized
outgoing handoff. Use the ownership boundary below; recording locally sends nothing.

## Recover, retain and reconcile

For ordinary Issue/PR work, read the canonical request, relevant discussion and
remaining acceptance, then use available **mafe-si:keep-a-worklog** to start or
recover the task area. At meaningful handback use **mafe-si:wrapup-the-worklog**.
When wrapup calls capture, complete its selected operation without another wrapup.
Without those skills, retain the current outcome, source, effects, decisions and
next check in the same outside-repository task folder. Recovery detail stays there;
checkpointing and publication are separate decisions. A status question or scope
correction does not cancel the original outcome unless the owner says so.

Inspect an existing target before editing. Use UTF-8 without BOM and read back
the resulting whole file. Retain outcome/significance, source or revision,
attribution, uncertainty, decisions, dependencies, next check and actor as needed
to resume. Keep observed, proposed, agreed and verified states distinct; use only
supplied priority and scheduling decisions. Child completion is not integration.

For deferred observations, search relevant coverage, retain concise context and
open questions in the authorized home, then resume the original task. A final
solution is unnecessary; speculative remarks need no record. Recording a deferred
finding does not select its execution or undo completed work.

Publish when reader-facing meaning changes: a warranted request, outcome, scope,
acceptance, decision, actionable blocker or next actor/action. A handback, merge,
passed rerun or receipt alone warrants no body edit, comment or notification.
Recompose the current account and reconcile contradictory linked active summaries;
keep closed delivery accounts as dated history. Preserve deliberately selected
detailed discussions and required audit detail. Keep essential qualified meaning
self-contained when evidence is private or local; a host path is not a shared link.
Do not copy recovery logs, hash inventories or execution chronology into issues.

Use available **mafe-si:reporting-for-humans** for composition, passing purpose,
readers, destination, essential claims and limits; capture retains placement and
publication decisions. Otherwise lead with the problem/result, decisions,
remaining acceptance and next action. Shared skills remain optional.

## Provider and ownership boundaries

Use the linked provider operations and read back canonical state after authorized
writes. After a lost receipt, inspect the target and search matching source/coverage
before retrying; an uncertain operation is not a confirmed failure. Preserve known
effects separately from missing ones. Never claim IDs, native edges or acceptance
from drafts, and never silently dispatch retained work.

Distinguish PR resolution from partial advancement or context. Use closing syntax
only for fully satisfied issues; link still-open acceptance without a closing keyword.
GitHub auto-closing depends on its default-branch rules; a merge alone proves no
issue transition. Read back issue state after delivery; when closure
is authorized and acceptance complete but the issue remains open, perform the
supported status update and verify it. Unmet acceptance remains open.

A dependency means the owned consumer is blocked by a prerequisite; relatedness,
checklist order and subissues are different. Use a native edge only with supported
read/add/remove and canonical readback. The current connector exposes no native
dependency operation; report that gap without claiming prose is an edge. Recheck
consumer acceptance after supplier completion and preserve partial intake success.

For incoming handoffs, preserve attributed requirements, source identity and
authority; suggestions remain suggestions. Return project, canonical links,
created/updated/already-covered disposition and gaps through the intake invocation.
Capture neither accepts implementation nor creates a reply or pickup duty.

An authorized outgoing handoff uses the receiving project's procedure or available
**mafe-si:coordinate-projects** with fresh owner context; without that transport,
report the gap. Do not contact another owner or write its records merely because
material was retained. Keep sources and likely ownership locally until authorized.
For lesson evaluation use available **mafe-si:extract-learnings**; already-formed
knowledge can follow the local docs path directly.

Return the accessible reference, retrieved/updated/created/already-covered
disposition and material gaps. Capture supplies no installation, implementation,
external-write, notification or completion authority.
